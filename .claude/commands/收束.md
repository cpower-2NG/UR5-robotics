# 收束（蒸馏 → 清账 → 守卫 → 双仓提交）

阶段结束、或 `test_queue_hygiene.py` 红灯时执行。按顺序走，任何一步红灯先处理再继续。

## 1. 蒸馏（把定案搬到该住的地方）

- 新的能力/验收结果、参数现值 → `docs/当前状态.md` 对应行**原地覆写**（行 ≤3 行 + 取值命令 + 上次核对 + 保质期；不是新增一行历史）。
- 新出现「某个事实该信谁」→ `docs/事实源登记.md` §2 登记路由（只登记家，不登记值）。
- 阶段出口达成 → `docs/阶段/README.md` 梯子更新状态 + 该阶段实验记录（冻结，只追加带日期的勘误）。
- 被推翻/作废的旧论断 → 回它**原位**改掉（恒久层原地替换），并在仓外台账记一笔。
- 判决过程与证据 → 追加仓外台账 `~/robotics/notes/ur5-vision-grasp/RESTRUCTURE_PLAN.md`（第 N+1 轮，只增不改）。

## 2. 队列清账

`docs/待执行命令.md` 里做完的条目**整段删除**，被删正文追加到仓外留档
`~/robotics/notes/ur5-vision-grasp/待执行命令-留档.md`，节头格式：
`## ☑ YYYY-MM-DD 队列清账：<条目名>`。

## 3. 三道守卫（全绿才许提交）

```bash
python3 scripts/test_deidentified.py     # 必须 0 命中
python3 scripts/state_check.py           # 无结构性错误（超期行只是提醒，但要过目）
python3 scripts/test_queue_hygiene.py    # 队列里只有还没做的事
```

## 4. 双仓提交

- 主仓（~/robotics/repos/ur5-vision-grasp）：按主题分 commit，中文一行式标题。
- notes 仓（~/robotics/notes/ur5-vision-grasp）：台账与留档的改动一起 commit（「台账 N：…」格式）。
- **不 push** —— push（GitHub 首推 / 推板子）是用户的动作，见 `docs/待执行命令.md`。
