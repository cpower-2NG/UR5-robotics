## 1. 为什么做、链路长什么样

前十轮把「抓点偏 3.5 mm」查到底：**不**来自腕部外参（5 位姿散差 1.13 mm / 0.31°）、
**不**来自夹爪装偏（A/B 转腕 180° 同向否证），来自 `top_face_center` 估计算法本身
⇒ 换 **GraspNet(graspness) 候选解算**。

**分工是硬约束**：板上没有 torch / MinkowskiEngine / graspness 权重、也没有外网；
开发机 WSL 不能当 ROS 节点 ⇒ **板上只做抓帧与执行，推理全在开发机，接缝 = SSH + 文件**
（`scripts/precision_round.py --push` 推脚本、逐个核对 md5）。

链路：巡检位抓帧（**抓帧窗口内关节峰峰 0.0000°** 才可信，关节角插值到图像时间戳）
→ 开发机 GraspNet 解算候选 → 选块（≤12 mm 锚定到点云顶面中心，score 只作 ≥0.20 门）
→ IK / 九航点计划 → 板上执行 → 巡检帧量误差。

## 4. 本段判决（已写进代码 / 文档）

- **放置高度按块底算**：`PLACE_CLEARANCE = 5 mm`，`place_z` 按实际块高算 —— 29.6 mm 的块
  不再压进台面（旧公式把 28.5 mm 当指尖偏移，块底落到台面以下 1.1 mm）。
- **放置水平补偿默认关**（`PLACE_COMPENSATE_ECC = False`）：抓取偏心**预测不了**夹持后的
  偏移（预测 6.44 mm vs 实测 2.76 mm；跨三轮无单调关系），补了反而多偏 4.3 mm。
- **夹持帧作废**：腕部相机看不到夹着的块（偏 tool0 侧面 91 mm、光轴竖直，夹持块整个落在
  画面外）⇒ `--held-capture` 直接拒绝。
- **规划器整链选支** IK 分支，不再只吃「上一个航点的解」；**夹爪指令必须给回调**（驱动的
  异步接口不给回调就是空操作——指令从来没发出去过）；夹爪单独验一次（不动臂只开合）。
- **两道闸门**：视野闸门（`survey_footprint.py` 把拾取区四角反投影回像素，要求 40 px 边距；
  `PICK_ZONE` 近边据此从 0.22 收到 **0.25**）＋ 光照闸门（彩色帧 p99 亮度 ≥ 60 —— 关灯会让
  每块颜色变 `unknown` 而整条链看起来没坏，2026-10-25 实测）。
- 续跑 `--resume` 从本地执行日志**最后一条到位航点**之后接，不重跑 approach/grasp。
