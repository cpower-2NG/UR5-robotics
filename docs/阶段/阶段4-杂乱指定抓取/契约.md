## 1. 任务场景

用户用**结构化命令**指定杂乱堆里的一块，系统在**接触 / 重叠**的块堆中定位到**同一个实例**，
选一个可执行的 6-DoF 位姿抓出，放到 3×3 宫格的指定格；S3/S4 还要求系统**自己移开遮挡块**，
最终全桌块都在合法终态。

- **指定通道（核心）**：`<color> <position>`（`red left|right|front|back|center`）、
  `<color> <relation> <color>`（`red left-of green`、`yellow on blue`）、`<color> top|bottom`、
  `at <x_mm>,<y_mm>` 或像素点击；可选 `nearest|largest|most_visible`。
  自由语言**后置**，不属于本阶段。
- **指定输出**：实例 ID + 颜色 + base 系中心 / 顶高 / yaw / 可见比例 / 置信度，**回显并允许人确认**。
- **块**：同一批 **29.5 mm 方块**，七色；拾取区沿用 `[0.25, 0.575, 0.17, 0.42] m`（base 系）。
  S3/S4 允许块间**接触 / 重叠**，**不再用 60 mm 最小间距**作规划前置。
- **S3 场景定义（2026-11-20 用户拍板）**：7 块 = 一个两层塔（上下同心 ≤3 mm、
  yaw 差 ≤10°，可同色或异色）+ 一对贴合 + 3 个孤立块（互不同色）。塔/贴合对
  最多产生 2 个重复色；垫纸恰好 7 个色格 + 2 个备用格吸收。
- **S3 放置=颜色归格**：每块按**实测颜色**进对应色格；同色重复块的第二块进
  备用格（按 id 升序 7 → 8）。格位唯一来源 = 解垫嵌进 `grid-pre.json` 的
  `grid_order`（mat 色序），计划/探针/判分/扫掠同读一份。
- **S3 指定进轮**：每块一条结构化命令（`--designate-file`，一行一条，顺序即
  执行顺序），在跑前**实测真值**上解析成唯一实例；0 匹配 / 歧义 / 与布局解析
  不一致 / 覆盖不全 ⇒ 执行前停。
- **S3 清障**：塔底若为目标，先移塔顶。`--clear-dest cell`（默认）把被清块放进
  它自己的格——若它本身是后面的目标，这一抓同时算它的目标抓取（每块只抓一次）；
  `--clear-dest free` 落自由区（E9 现状，之后还要再抓一次）。
- **S3 塔下层颜色**：顶面被压住 ⇒ 从**侧面带**实测（跨帧置信裁决）；同色塔
  不可辨时按布局同色填充并标明 `same_colour_prior`；异色塔不可辨默认
  fail-closed（显式 `--allow-side-colour-fallback` 才按清单填充并标 fallback）。
- **场景批次**：

  | 批次 | 内容 | 块数 | 出口 |
  |---|---|---:|---|
  | S0 | 隔离基线（主组固定布局库） | 5 | **硬出口** |
  | S1 | 异色接触 | 6 | **硬出口** |
  | S2 | 同色接触 | 6 | **硬出口** |
  | S3 | 两层重叠 | 7 | 进阶 |
  | S4 | 自由布局 + 压遮 | 9 | 进阶 |

  **真机一律自由摆位**（2026-11-15 v0.8，用户拍板）：拾取区内人随手摆，
  **跑前 pick burst 实测 = 规划与判分真值**（该链 2026-11-13 起已在用）；
  不再按固定布局摆块，摆位引导图 / A3 摆位图 / 布局偏差归档流程随之退役。
  S0–S3 的固定布局 JSON **退役为仿真/复现资产**（需要前后对比时才显式用）。
- **判分**：指定实例是否抓对、是否抓出、是否放到指定格、全桌终态是否合法、
  过程有无碰撞 / 掉落 / 人工干预。**S0 / S1 / S2 分开报**，不合并成一个「S0–S2 总成功率」。

## 2. 与阶段 3 的技术与设备差异

| 维度 | 阶段 3 | 阶段 4 |
|---|---|---|
| 感知 | 顶面栅格 + 高度掩码 + 4 连通（同高接触块会**合并**） | **多线索实例分割**（3D 聚类 / 顶面矩形 / 凹角与分水岭 / 颜色 / 尺寸先验） |
| 抓取 | 固定俯视 `Rz(yaw)·Rx(180°)` | **6-DoF 候选池**（GraspNet / RNGNet / 几何兜底）+ 统一过滤选择 |
| 规划 | 内部几何检查 + 60 mm 护栏 | **计划 JSON v2 契约冻结 + 后端可切换**（urkin 现在；cuRobo S3 前评估）+ **MoveIt 只读裁决**（段级 `/check_state_validity`，模型含夹爪）；接触场景关 60 mm 护栏（探针 OBB + 段级裁决替代，2–3 mm 余量） |
| 相机 | 腕部单路 | 腕部**单相机三视点**（pick / free / pad；不再有固定俯视第二路） |
| 目标 | 格心（自动选块） | **人指定实例**；关系 / 遮挡图 + 结构化谓词 |
| 测量 | 逐层顶面 | 腕部三视点共识真值 + 布局清单；俯视对中 / 偏心**已取消** |
| 接缝 | SSH + 文件 | 同左（DDS 通了才升级，文件接缝**保留为回退**） |
| 不变 | AG-95、UR5、垫与 `grid.json`、执行三闸、单一投影点、逐次授权 | 同左 |

**关键技术事实**（决定设计，不许在实现里绕开）：

- 颜色**只能**在「真有两类」时参与分裂：**不同色**接触块（S1）可凭颜色类拆开
  （2026-11-11 §20.4，s11 原始帧做回归）；**同色**接触块（S2）找不到第二类，
  仍必须靠几何 + 尺寸先验。
- 腕部相机**看不见夹着的块**（2026-10-26 实测）⇒ 不存在「抓完用腕部拍一帧验证」；
  **抓取确认 = 夹爪回读 + 跑后腕部三机位复测**（2026-11-11 v0.6）；偏心只在日志里
  报告，不做闭环。
- **规划为什么不是「全用 MoveIt」**（决定生成器/裁决的分工，2026-11-14 定型）：
  ① 开发机不在 DDS 图内（AGENTS §4）——规划曾只能在本机跑，而本机没有 `move_group`；
  ② 真机模型 2026-11-13 前无 AG-95 几何，MoveIt **查不到「夹爪撞臂」**（attempt6，C153A3）；
  ③ 真机组 KDL 曾随机重启不可复现（D60，2026-11-13 实证已修）；
  ④ 契约要求计划**逐位可复现、可离线单测**（§4.4 不许中途改代码），随机搜索规划器与此冲突。
  ⇒ 分工 = **数值 IK 做确定性生成器、MoveIt 做碰撞/状态有效性裁决、JTC 做执行**；
  后端接口可切换（cuRobo 走同一份计划契约）；MoveIt 的不可替代职责 = 裁决，不是生成。
- **【存档】俯视外参无声过期**（实测一天漂 0.945°）；「昨天标过」不构成今天的证据。
  俯视深度稳定读远 ~1.9%，是相机属性不是漂移。俯视已退出阶段 4，本条只用于
  复现旧证据。
- **【存档】四条边分开**：① `base`↔`base_link` 180°；② `tool0`↔`camera_link` 手眼；
  ③ `camera_link`↔`optical`（D435i 实测 15 mm）；④ 俯视固定外参（垫 PnP）。
  15 mm **不是**手眼偏置，`STAGE3_CAMERA_OFFSET` **不是** link→optical。
  其中 ①②③ 仍是腕部链的有效事实，④ 随俯视退出只作存档。
- **【存档】认相机只认外壳标签的 SDK 号**；两路相机的参数文件 `serial_no` 必须不同——
  相同 ⇒ 两个节点抢同一台相机，联合标定会变成「自己跟自己比」的 0 mm 假绿。
  阶段 4 正式轮只用腕部一路，此条只在复现旧证据时相关。
- **【存档】同一 TF 树只允许一个 `camera_link` 父节点**；腕部手眼 TF 由板上独立脚本
  发布，俯视只准用 `topcam_link`。俯视退出后此约束只在旧栈复现时相关。

### 3.1 E3a / E3b 的分工（不许混）

> **【存档】3.1–3.2 全部是俯视入口门的实施细则，2026-11-11 随俯视退出，不再执行。**

- `topcam_drift_check.py` 是**探测器**，只有两种结论：**1 = 看见了变化**（外参作废）、
  **2 = 看不清**（证据不足 / 环境不满足）。**它不再返回 0。**
- 「外参是否仍有效」**只能**由 E3b 的垫/板 PnP 直接解一次回答；
  光流静止 **不是** 通过的理由（相机静止与亚 2 px 漂移在像里不可分）。
- E3b 每轮次序固定：drift 筛查（1 或 2 都进 PnP，**都不放行旧值**）→ 板 PnP `--solve` →
  与存盘外参比（>1 mm / >0.2° ⇒ 重解）→ 重解仍超 ⇒ **停车** → 新外参两路垫交叉核对
  （**判据 B，2026-11-07 用户拍板**：≤2 mm / ≤1.2°）。第 1 轮没有「上次的图」时明确记
  「无法 drift，只凭 PnP」，**记录在案，不假装做过**。

> **判据修订（2026-11-07，用户拍板，台账第二百七十二轮）**：E2 / E3b 的俯视外参由
> 「两路绝对一致 ≤0.5°」改为**按自洽性判**。理由：8 个可评轮次的角度 0.31–0.89° 全部压在
> **腕部链条 ~1° 的姿态倾角误差**上（同一块静止板换姿态差 9.87 mm / 1.180°），而两条互相
> 独立的外参路线（垫相除 / 板 PnP）给出同样的 0.79–0.94° ⇒ 0.5° 在这套硬件上不可达，
> 不是垫或俯视的锅。**平移门 2 mm 未动**；1.2° 是垫路线的自复现性，不是放宽到「随便过」。
> 用户同时要求保留**可修正性**：夹爪夹方块时用机械固定夹距当已知长度核对俯视量出的距离，
> 用得到的比例/偏置修正后续测量（列在 E4b 一侧的待验证项，见入口实验 §6）。
> **2026-11-11：E4b 取消，这条可修正性路线随之下线（入口实验 §16）。**


### 3.2 E4a 的取消条件

悬停位可见性不达标时先**换悬停位**（水平偏移 / 高度），仍不达标 ⇒ 按主计划书
「**取消该功能**」，写进台账与本契约悬案，**不硬凑**、不降低可见比例与精度阈值。

## 4. 出口判据

### 4.1 主命题

**在接触 / 重叠的杂乱堆中，用「颜色 + 方位 / 关系」把用户指定的那一块定位为同一个实例，
并在碰撞约束下抓出、放到指定格**；S0–S2 能达到硬出口，S3/S4 报告能做到什么程度。

- 分析单位 = **块级尝试**（一个指定块的一次完整抓放；含移遮挡，只对指定块计一次）。
- 分母 = 该轮**全部指定块**，不剔除失败块。
- **void**（外部原因未完成）不计入分母但记录原因；同一判据连续 3 次 void ⇒ 停。
- **fail**（系统原因）计入分母，算失败。
- 失败必须**分类**（感知 / 候选 / IK / 规划 / 执行 / 放置 / 人为），不能只报「失败」。

### 4.2 测量协议

1. **`rc=0` 不算成功**：抓取成功 = 指定块被抓出、抬到验证位、未掉、未抓错，
   由**夹爪回读（`gripped` + `slip`）+ 跑后腕部三机位复测**确认；**人眼可选**，
   只在判分器给出 `person_review` 时作为放行人（`rc=0` 永远不算确认）。
2. **放置格**由**该轮实测垫参数**（pad solve 的垫面 z + 足迹）与跑后腕部三机位判
   （不压线、不越界）；人眼可选。
3. **终态**测全桌：所有块在合法格 / 自由区，不重叠、不落地、不越界。
4. **人眼复核可选**：只有判分器要求 `person_review` 时，未填复核意见不得判 `ok`；
   其余轮次不需要人填。
5. 测量来源不得复用控制感知：判分走独立测量链（E13）。
6. 每轮测量用**该轮 pad solve 的实测垫参数**（`grid-pre.json` 自 2026-11-13
   **自洽**：`pad_thickness_m` = 解垫垫面 z、`pad_footprint_m` = pad-spec 实测足迹，
   由 `--pad-spec` 嵌入）与跑后腕部三机位；仿真跟真机同一常数（§20.5）。
   **俯视闸门已随俯视退出（2026-11-11）**；`site.yaml` 只做启动参数落盘副本。

### 4.3 S0–S2 硬出口判据

| 判据 | 定义 | 通过 | 不过时动作 |
|---|---|---|---|
| 指定 ID 正确率 | 系统选中的实例 = 真值指定实例 | ≥90% | 停，查分割 / 解析 |
| 抓取成功率 | 指定块被抓出、抬到验证位、未掉、未抓错 | ≥80% | 停，查候选 / 执行 |
| 放置格成功率 | 指定块落在指定格内（不压线、不越界） | ≥90% | 停，查放置 |
| 全桌合法终态率 | 所有块在合法格 / 自由区，不重叠、不落地、不越界 | ≥90% | 停，查移遮挡 / 复位 |
| 安全事件 | 碰撞、掉落、非预期运动、急停 | **0** | 立即停轮 |
| 人工干预 | 除授权 / 摆场景 / 确认外的动作 | **0** | 该轮按原因记 void / fail |
| 自主 top-1 | 不追问直接选中 | 单独报，**不设硬门** | 能力指标，不混入 0 干预 |

**前置**：E0–E8（M1/M2 硬门；E2/E3a/E3b/E4a 随俯视退出，2026-11-11）全过；
相关支撑门（E13/E15/E20）全过；跑后腕部三机位复测可用；垫参数取该轮实测；
attach/detach 无错误；**段级碰撞裁决可用且模型含夹爪**（A1/A2，2026-11-13）。
（每轮俯视漂移闸门与抓前对中 / 偏心补偿已于 2026-11-11
删除，见 v0.6 同步说明。）

### 4.4 轮次与达标（2026-11-15 v0.8：能力清单 + 集中批次轮）

**为什么要改**：连击 streak（连续 3 轮、中间不改码否则重计）把基础设施故障和
能力证据混进同一个计数器 —— 8 次真机尝试 streak 0/3，唯一物理完美的轮
（2026-11-12 attempt2：五块全抓对放对、零安全事件）因跑后一组取证 burst 掉
TF 被 void 归零。技术验证本体早已成立，卡住的是验证结构 ⇒ 对照是添头，
出口按**能力证据**判。

- **S0 = 1 轮链路验证轮**：整轮 rc=0 且判分可判（非 void）即过。它是编排链的
  冒烟，也是七项性能优化（2026-11-12 #16–#22）的首次真机验证
  （timing.json 回填校准 `--compute-est`）。
- **S1 / S2 = 各 3 轮集中跑**：同一晚连续、中间不改代码 / 阈值；**块级尝试池**
  （3 轮 × 每轮全部指定块）合并按 §4.3 四率门判，S2 单独统计。不过门 ⇒ 按
  失败分类停下改设计，**不无限刷轮**；补跑记为补充批次并写明原因。
- **S3 / S4 = 各 1–2 轮演示**，报告制：成功率 + 失败分类，阈值由用户看完数据
  后拍板，本契约不预设硬门（E9 真机「连续 2 场全绿」2026-11-10 已达成，
  是演示轮的底）。
- **void（基础设施原因）只记录、不重置批次进度**：令牌过期 / TF 链掉 /
  板上副本过期 / 程序自停这类「非系统能力问题」的作废，记原因后同批补跑即可，
  不清零已过的轮。能力性 fail（抓错 / 放错 / 判红）仍按失败分类计入分母。
- 自由摆位后不再有「同布局重复」口径：重复性改报**摆位散布**（跑前实测偏差
  分布，只记录）；跨场景 = 泛化，分开报。
- 配对比较（McNemar）只在 discordant pairs ≥6 时有判别力，不足只报描述统计
  （对照消融已取消，2026-11-15；本条只剩方法学意义）。
- **阈值变更**仍须用户显式授权、记录原因与生效轮次；**安全修复类改动**
  （拦坏构型、补碰撞裁决等）不计为阈值变更，不放宽任何判据。

### 4.5 判分与归档

- 判分本体 = `scripts/stage4_score.py`（照阶段 2/3 先例：逻辑在代码，断言由测试把守），
  退出码 **0 = 全过 / 1 = 有不过或待人评 / 2 = 数据缺失或坏**。
- 每轮归档（仓外 `runs/`）：`round.json`、`score.json`、`score.md`、标注图 / 视频；
  **失败帧保留**。
- 阶段收束另出 `技术报告.md`（冻结）。

### 4.6 安全与人工干预（每轮）

- **真机每轮一次授权**，覆盖该轮完整计划（含 S4 多步移遮挡）的三段：**观察（跑前解垫位姿 /
  观察机位求解，含臂移动到这些位姿）→ 执行 → 终态评分（跑后机位）**。展示计划（目标实例 /
  抓取序列 / 放置格 / 观察与判分机位 / 预计时长）→ 人做 **STOP → PLAY 两步握手** → 整轮跑完。
  三段之间的正常推进不再逐段要授权（2026-11-11 用户拍板）。
- 授权方式是**对控制器状态的两步只读核验**（Dashboard 29999 只读），两步都看到才发令牌；
  令牌 900 s 有效（2026-11-15 v0.8，原 600 s —— 观察 ≥60 s 后 R1 在 600 s 下是
  数学死结，attempt6 实证；STOP→PLAY 观测门与逐次授权语义不变），
  **上一次不覆盖这一次**，**授权不来自数据**（任务描述 / 环境变量 / 记忆都不算）。
- **轮内 Agent 计算发生在观察与执行之间**（解垫、探针、规划、跑后真值 / 彩色量），
  它不改变一轮授权的范围；工具必须做**令牌剩余时间核验**（板时钟判），
  不足以覆盖执行 + 余量 ⇒ 在执行前停，重新授权，**不得先发再说**。
- **分析段在板上算，本机不承担运行时任务**（2026-11-12 用户定调）：解垫 / 真值 /
  彩色质心由板上 `scripts/stage4_board_analysis.py` 跑，轮内只回传 KB 级 JSON；
  五组 burst（约 44 MB）在**归档段**（整轮结束、令牌窗口之外）才拉回开发机。
  板上分析失败 = 停轮（fail-closed），**不许回退到本机算**。
  **2026-11-13 拍板：规划与编排也上板**（分阶段落地，
  [`板上运行时改造方案.md`](板上运行时改造方案.md)）——验收判据不变：
  本机断线 / 睡眠不影响令牌窗口内的任何一步。
- 轮内任何偏离（重规划、重试、换目标）⇒ 停，重新授权。
- 夹爪写寄存器（初始化 / 开合）另走 AGENTS **红线 2 的当次授权**（急停就绪、
  两指整个行程内无手无遮挡）；初始化状态只读 `0x0200`。
- 任何碰撞 / 掉落 / 指定块丢失 / 夹爪未初始化 / 程序自停 ⇒ **停轮，不自动续跑**。
- 执行中令牌过期 ⇒ 记 `aborted_token`：本轮 void、**不计入连续 streak**，
  也**不记抓取失败**。

### 4.7 b̂ 偏置补偿（2026-11-15 v0.8 降级为**记录项**）

定义不变（阶段三 §4.1 实测：机放块落地后系统性偏 `(−x, −y)`，住在块↔夹爪之间，
闭环改目标消不掉）：

```
b̂  = 实测块顶中心 − 命令目标
命令目标 = 期望目标 − b̂
```

- **阶段四口径 `fixed`**：整轮一个 b̂，一律作用在**放置命令**上（`cell_center − b̂`）；
  `desired_center_mm`（格心）与 `commanded_center_mm` 分开落盘。
- **缺种子不再停轮**（v0.8，用户拍板）：`--bias-seed` 与 `<run>/bias_estimate.json`
  都没有 ⇒ 自动按未补偿跑（mode `none`、source `none-unseeded`），报告与 facts
  标「未补偿」。b̂ 对 30 mm 判格容差是 ~3 mm 量级的锦上添花，不值得为它停一轮
  真机。显式 `--bias-comp none` 行为不变。
- **测量帧与判分帧一致**：仍用**彩色顶面质心**算 `b̂_round = 彩色质心 − 命令`；
  与阶段三 n=40 先验差 >5 mm **只记录**，不再强制停下来查口径。
- **`|b̂| > 15 mm` 不当偏置**：该块按失败记（掉了 / 没抓住 / 被撞）——保留。
- 每轮跑完并入 `<run>/bias_estimate.json`，**只定下一轮种子，不改本轮已执行命令**。
- **判分口径不变**：仍比实际块心 vs 格心；补偿只改善它，绝不放宽判据。

## 5. 明确不做

- 自由语言解析（结构化语法为核心，NL 后置）；学习式实例分割训练（S2 不够再单独立项）。
- 非方块 / 任意物体（阶段 5）、多块同抓、动态目标、传送带。
- 把仿真成功当阶段出口（仿真只做预验证）。
- **阶段 4 内重启俯视路线**：不改造成「可选开关」接回正式轮（要重启必须新开版本
  重新拍板，2026-11-11）。
- 无限次抓前对中闭环（≤2 次修正）；把偏心补偿与放置偏置 `b̂` 混为一个量。
- 在真机上做未经当次授权的运动 / 夹爪写寄存器。
- 拿俯视绝对深度当高度判据（深度的 ~1.9% 偏差是相机属性）。
- 「抓完用腕部拍一帧验证」（腕部看不见夹着的块）。
