### 7.3 用户提的修正办法：夹爪夹距当已知长度

思路（2026-11-07 用户原话的意思）：**俯视拍到「夹爪夹着方块」时，用机械上确定的夹爪夹距
和俯视量出的距离对比，把比例/系统偏差修出来**，再用它修正后续测量的位置差。

- 已知量：AG-95 的开合是寄存器给定（0–1000 千分 → mm），两指外侧面间距由机械结构确定，
  是这套系统里**唯一不依赖任何相机**的长度基准。
- 量法：同一帧里取两指外侧面（彩色边缘 + 深度的平面/高度），量间距，与机械值比。
- **精度预算（先算再干）**：俯视在台面上约 **0.64 px/mm**（1280 px / ~2 m 视场）。
  26 mm 开口的 2% = 0.52 mm ≈ **0.33 px ⇒ 单帧不可辨**；100 mm 开口的 2% = 2 mm ≈
  1.3 px ⇒ 单帧可辨、20 帧融合有余量。**所以先用大开口验证，再往小开口推**；
  小开口上只能验证「有没有大偏差」，不能验 1%。
- **前提必须先验**：两指细、金属反光、大概率被所夹方块挡。第一件事是收一帧「夹爪夹着块、
  俯视可见」的图，确认两指在彩色/深度里**能不能稳定分割**。
  **2026-11-08 B1 已做（部分）**：全开（1000 千分）+ 无遮挡的低位帧证明两指**可稳定分割**，
  并顺带测出 **AG-95 开合轴 = `tool0` 的 x 轴**；**夹着块**的那一帧仍未拍（列在队列，
  等第一次真抓取时顺带取，不单独上臂）。分不出就换已知长度：
  方块本身有已知规格（外接边长可当尺度），或 ChArUco 板（已知边长）—— **不许把不可测
  当成可测**。
- **它能修什么**：比例/深度系统偏差（俯视深度读远 ~1.9%、y 向 20–45 mm 偏差的量级）。
  **它修不了倾角地板** —— 那是腕部链条的姿态误差，只能靠 E2 判据 B 的边界兜住，
  或回头做多姿态手眼（判据 A 那条路）。
- **怎么算有效**：修正后在 E4b 对中判据（≤2 mm / ≤2°）内即算有效；若修正前后无差别，
  就记「地板内、无增益」，不硬上。
- 需要一次真机（夹住方块、静止拍俯视），属运动 ⇒ 需当次 STOP→PLAY 授权。

**前提帧 B1 已拍（2026-11-08，✅ 可分；空夹爪、大开口、无遮挡）**

- **几何先算清**：悬停高度（tool0 z=547 mm）俯视**完全看不到夹爪** —— 整个夹爪的投影都在
  画面上沿之外（tool0 落在 v≈−300 px），所以「抓完拍一帧验证」这类设计本来就不可行。
  tool0 降到 **z=360 mm** 时指尖投影到 v≈131 px、进画幅；再降到 240 mm，肘离台面只剩
  35.8 mm（护栏 20 mm）⇒ 取 **360 mm**（肘余量 155.8 mm）。
- **实拍**：`runs/2026-11-08-stage4-entry/e2/set4/b1/topcam/`，20 帧，tool0=(472,−250,360) mm，
  到位误差 0.00°、窗口内关节峰峰 0.005°。**没有写任何夹爪寄存器**，开口沿用上次遗留状态
  （所以这一步不需要夹爪授权）。
- **结论：两指可稳定分割。** 彩色阈值 V<110 把夹爪整体吃住、两指之间保持空白（空隙约
  40–50 px，背景不被误选）；深度窗口内 98.4% 像素有效，两指可见实体的 base 系中心距
  **79 mm**，跨 4 帧一致到 1 mm。
- **附带测出一条一直缺的事实**：AG-95 的**开合轴是 tool0 的 x 轴**。`precision_plan.py` 里
  原先写着「AG-95 的手指轴相对 tool0 的方向没有文档也没实测过」。用 FK 把 x±35 / y±35
  投影回帧上：橙色 x±35 正好落在两只指头上、绿色 y±35 落在指间空隙（等轴几乎平行于
  视线方向）。⇒ 以后要用抓取平面内角时，开合方向 = `Rz(ψ)·[1,0,0]`。
- **还差一步**：本帧是**空夹爪 + 大开口**（最有利几何）。比例修正本身要「夹着块」的帧，
  但**必要前提（可分割）已经成立**，那张帧可以等第一次真抓取时顺带拍，不必单独上臂。

| 真值复用了控制感知（E13 存在的理由，契约 §4.2.5） | `truth.truth_source` 必须在白名单（`topcam-independent` / `human-annotation` / `layout-manifest+topcam`）；写 `perception_3d` 之类 ⇒ **整轮 `missing_data`**，退出码 2 |
| `rc=0` 当抓取成功 | 成功 = `exec_rc==0` **且** `lifted` **且** 未 `dropped` **且** 未 `wrong_block`，**且** 俯视/腕部/人眼三路 `confirm` 全 true。抬起了但缺确认 ⇒ `person_review`，不是绿 |
| void 混进分母 | void 不进分母（`n_void` 单列）；**整轮率的分母是 `n_scored`**。连续 3 次 void（轮内，或连续 3 个 void 轮）⇒ 停 |

### 9.3 出口：连续 3 轮，改判据即重来

`--exit` 按契约 §4.4 数连续轮次：**任一轮红、或某轮的 `thresholds` / 代码哈希
与计数起点不同 ⇒ 连续计数从该轮重起**。「偷偷调门槛凑绿」在报告里会显示成
`restart`，凑不出 3 连；连续 3 个 void 轮另给 `⛔ 停`。

所以跑轮侧要把自己的代码指纹写进 `round.json.code_hash`，判分器原样透传、参与连续计数 ——

## 10. E8 MoveIt 场景 / attach / 规划（本机仿真，2026-11-08）

**判据**（契约 §3）：M1 无假碰撞；M2 20/20 无碰撞；attach/detach 正确。
**场地**：本机 Gazebo 仿真（S1:0，6 块杂乱）+ 实验室真机（6 块实摆）。**两半均已跑（2026-11-08）**，
真机半段见 §10.8。

### 10.1 工具与独立性边界

- `scripts/stage4_moveit_probe.py` —— **只调服务**：`/apply_planning_scene`、
  `/compute_ik`、`/compute_fk`、`/plan_kinematic_path`、`/check_state_validity`、
  `/get_planning_scene`。**不发 `/move_action`、不碰控制器，臂不会动。**
- `scripts/stage4_scene_model.py` —— **独立碰撞核验器**（OBB + 15 轴 SAT），
  65 项自检含 4 条变异。几何逐字取自 `ag95.urdf.xacro`，不做 FK（位姿由 `/compute_fk` 给）。
- **独立性边界（写在这里是为了不夸大结论）**：夹爪（本体 + 两指）是本仓自己建的
  **盒子**，可以独立核验；UR5 臂杆在 `ur_description` 里是 **mesh**，本核验器没有
  臂杆几何 ⇒ 凡是「臂碰到东西」的判定，只能**借用 MoveIt 自己的接触报告**。
  所以 M1 的独立仪器只覆盖夹爪，臂的结论不是独立的（代码 docstring 里同样写明）。

### 10.2 M1 无假碰撞

**M1a（24 个悬停位 = 6 块 × 2 个 yaw × 指尖离块 10/50 mm）**，每个位姿走这条链：

1. 免碰撞 IK（`avoid_collisions=False`）从**好种子池**（起始关节 + 至多 3 个 MoveIt 判过
   VALID 的解，按 `same_joints` 去重）解出候选；
2. 独立核验器量**闭合手指**与所有块/桌面的 OBB 间隙；
3. 对该解跑 `check_state_validity`；
4. 状态有效 ⇒ 再要求**碰撞感知 IK**（以该解为种子，1.0 s）也给出解——
   这样「拿不到」只可能是**被拒**，不可能是搜索失败。

判定：`ok` / `false_collision`（独立核验说空着、MoveIt 却拒）/ `unreachable`（两种 IK 都解不出）/
`gripper_collide`（独立核验自己就判手指碰物）/ `blocked_arm`（真实臂-物接触）。
**通过条件**：`ok ≥ 8`，且 `false_collision = unreachable = gripper_collide = 0`。

**M1b（反假绿灯：证明场景是活的）** —— 把 tool0 放到块心上方
`block_z + 本体高 60 mm + 指长/2 72.1 mm = block_z + 132.1 mm`，闭合手指**几何上必然**
与块重叠。种子取 50 mm 悬停位的解（直接从原位往往 IK 解不出）。
**必须全部被拒**——6/6 被拒才算场景真的发布进了 MoveIt，否则 M1a 的「全 ok」没有意义。

### 10.3 M2 规划 + 独立核验

- 目标：同一批 24 个位姿，`PositionConstraint` = **5 mm 球** + `OrientationConstraint` 0.01 rad，
  走 `/plan_kinematic_path`，规划时间 8 s。
  （1 mm 球时 OMPL 的目标采样会偶发超时，把「规划失败」和「碰撞」混在一起 ⇒ 放宽到 5 mm，
  到位精度另由下面的独立核验兜住。）
- **核验不看 MoveIt 的结论**：对每条轨迹按关节空间 **5 cm** 步长插值，逐点 `/compute_fk`
  再算夹爪（全开，比闭合更占地方）与块/桌面的 OBB 间隙，余量 **3 mm**（接触场景）。
  任何一点 `gap ≤ 3 mm` 记一次碰撞采样 ⇒ 该条判红。
- 规划失败要分类：对该位姿跑一次碰撞感知 IK —— 有解 ⇒ `plan_failed`（规划器没找到路径，
  不是碰撞）；无解 ⇒ `pose_blocked`（真被挡）。
- **通过条件**：规划成功且干净的轨迹 **≥20 条**，且**碰撞采样 0**。规划器没找到路径单列
  （不是碰撞，但会吃掉配额）。

### 10.4 attach / detach 的两条实测口径（都踩过）

1. **发的是世界位姿**：`object.header.frame_id = base_link` + 世界位姿，MoveIt 自己换算到
   连杆系。实测读回 `R_link⁻¹·(world − link_p)` 与换算值逐位相等。
   发「link 系局部位姿」或「frame=link + 世界位姿」都不对。
2. **`GetPlanningScene` 的读回陷阱**：`primitive_poses` **永远回单位阵**，真位姿在
   `CollisionObject.pose`。只读 `primitive_poses` 会把「位姿对不对」错判成
   **628.72 mm 误差**（数值恰好等于 |块世界位置|）——这个错误结论已撤回。

判据：attach 后物体从 `world` 消失、进 `attached` 且 link 系局部位姿误差 ≤2 mm；
detach 后回到 `world`，位姿误差 ≤1 mm、角度 ≤0.2°。实测 **0.00 mm / 0.00°**。

### 11.3 C 档为什么一块也没比 B 档多（全扫描，3 场 19 块 456 个位姿）

| 接近方向 | ok / 试 |
|---|---|
| 竖直向下 `axis2−`（B 档） | **49 / 76** |
| 竖直向上 `axis2+` | **0 / 76** |
| 水平 ±块 x / ±块 y | **0 / 76 ×4** |

- 横向/朝下的失败里，`gripper_collide` 占 68–75/76，且**零间隙来源几乎全是 `table`**：

### 12.1 工具与口径

- `scripts/stage4_clear_probe.py` —— **只调** `/apply_planning_scene`、
  `/get_planning_scene`、`/compute_ik`、`/compute_fk`、`/check_state_validity`；
  **不发 `/move_action`、不写夹爪寄存器**，臂不会动。
- 一次尝试（一个布局 × 一个指定目标）：
  1. **目标可抓否**：E7 的 B 档口径（竖直向下 4 个候选位姿），夹爪全开、自有 OBB 算间隙；
  2. **清障**：见下；
  3. **放置位姿**：把目标放到指定宫格格心（垫面上），用同一套几何核验「能在那个位姿接近/放下它」；
  4. **终态合法**：契约 §4.3 —— 所有块在合法格 / 自由区、**不重叠、不落地、不越界**。
- **两类遮挡，顺序固定**：
  - **压在目标上的块**（`stage4_clear_model.dependents`）：不是夹爪碰不到，而是一动目标
    它就会掉。**必须先挪走**，否则终态必然「悬空」。
  - **挡住夹爪的块**（`blocker_scores`）：按「挡住的候选位姿数」从多到少挑。
  两类都要**先确保它自己可动**（递归：它也可能被压/被挡），再在自由区找一个
  离现有块 ≥5 mm 的落点，用 IK + 碰撞核验「能把它放到那儿」。
- **成功 = 存在清障方案 ∧ 目标可抓 ∧ 放置位姿合法 ∧ 终态合法。**
- **独立性边界**照抄 E7/E8：夹爪是三个 box 可独立算；UR5 臂杆是 mesh ⇒ 臂的接触
  只能借 MoveIt 报告。**不验接近/退出路径**（E8/M2 的事）；真机的「不丢、不掉、不撞」
  要实际执行，**不在本探针里**。
- **终态判定的唯一实现**：`stage4_clear_model.terminal_report`。离线自检
  `test_stage4_clear_model.py` **48 项**（含 4 条变异）；宫格/垫/拾取区/桌面尺寸
  反查 `arm_grasp_sim/scripts/gen_scene.py` 的源码，不另抄一份。

### 12.3 两个不能读大的结论

1. **S4 的「100%」不是清障机制反复起作用的证据。** 40/45 次 0 步清障：这套夹爪
   开口 95 mm，两指位于 ±47.5–69.5 mm，**跨得过 29.5 mm 的塔**（本体在塔顶之上）；
   两对贴面块也能从自由轴竖直抓。**S4 的杂乱对 B 档竖向抓取不构成遮挡** ——
   门过是因为终态确实合法，不是因为「清障很难但过了」。
2. **清障步数不可逐次复现。** IK 种子池随尝试顺序扩张（同一布局、不同场次顺序，
   臂会落在不同分支），E7 里的 `blocked_arm` 类失败在 E9 里有时直接可抓、有时清一步
   也能过。**可复现的是「存在清障方案」这条存在性判定，不是步数。** 这也解释了
   E7 的 5 个失败块：只有纯 `gripper_collide` 的（S2:3 block-4、S2:4 block-4）
   是稳定遮挡；另外三块（S2:4/0、S3:2/0、S3:4/0，E7 判 `blocked_arm`）依赖 IK 分支。

### 12.4 一个假绿灯（v1 作废，留现场）

v1 跑出 `45/45、清障 0 步`，但那是**终态判定写错**：`terminal_report` 的「压在另一块上」
只比高度（±1 mm）且只要求两块**不穿插**（`separation >= -pen_tol`）—— 塔顶块在塔底
被挪走后，会被**远处同层块**「支撑」，判合法。S4 每场的塔底目标实际会留下悬空的 8 号。

修法（`scripts/stage4_clear_model.py`）：
1. 支撑必须**真的接触**：高度对上 **且** `separation <= 1 mm`；
2. 新增 `dependents()`，探针的 `ensure_graspable` 成功条件改成「可抓 ∧ 顶面无块」，
   依赖块优先于挡夹爪的块处理。

自检钉住：塔底挪走后塔顶判悬空、孤立块抬到塔层高度不被远处块「支撑」；变异测试把
支撑判定退回旧式（`>= -pen_tol`）⇒ 用例必须变红。v1 报告以 `-v1-superseded` 留档，
**不得引用其数字**。

50 mm，靠「瞄歪一点」在物理上撞不到邻块 —— 实时碰撞注入在这个布局里构造不出来。
另外三类的后果都可以**直接作用在评分器的输入**（终态真值）上，而这正是「防假绿灯」
要验的对象：评分器看到的世界坏了，它必须红。

**阈值承重**（`test_sim_s0_e2e.py` C 节）：同一个 12 mm 落点偏差，20 mm 容差下
**放过**、5 mm 容差下**抓住** —— 证明容差真的接线，且默认 20 mm 是会漏 12 mm 的。
**变异检验**：把 `others_unmoved` 容差改成 100 m、`slot_tol` 改成 100 m、
抬高门槛改成 −1 m、`pass` 聚合改成恒真 —— 四条**全部被自检抓住**（对应断言变红）。
