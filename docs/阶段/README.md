## 1. 阶段梯子

阶段按**任务场景的变化**划分，不按工作项划分。加新的视觉/运动模块、场景复杂度
上台阶 = 换阶段。

| 阶段 | 任务场景 | 出口判据 | 状态 |
|---|---|---|---|
| **1 · 点对点抓放** | 单个或少量方块的**点到点抓放**（俯视相机 + 单目标定位） | A1 真机验收 **4/4 抓放 + 槽位用尽收工** | ✅ 2026-10-05 |
| **2 · 多类分拣** | **多类物体 + 按类放置** | 待写进该阶段契约 | ⏳ 下一阶段 |
| 3+ | 待定（预期方向：更多视觉/运动模块 → 分拣、搭积木等） | — | — |

### 当前阶段的范围界定（随阶段变）

阶段 1 覆盖**单个或少量方块的点到点抓放**。**不涉及** 6D 位姿估计、堆叠场景、
动态目标与非立方体目标。

## 2. 每个阶段进入时要写一份契约

`docs/阶段/阶段N-<场景>/契约.md`，六项：

任务场景 / 与上一阶段的技术与设备差异 / 入口判据 / **出口判据** / 明确不做 / 悬案。

**出口判据要写成可执行的**（照 `scripts/board_a1.py` 的判分先例）——
**写不出可执行判据的项，不算出口。**

> **契约的边界**：**只写判据与边界**。
> 不写工作项（→ `../待执行命令.md`），不写现状（→ `../当前状态.md`）。
