## 1. 阶段梯子

阶段按**任务场景的变化**划分，不按工作项划分。

| 阶段 | 任务场景 | 出口判据 | 状态 |
|---|---|---|---|
| **1 · 点对点抓放** | 单个或少量方块的点到点抓放 | A1 真机 **4/4 抓放 + 槽位用尽收工** | ✅ 2026-10-05；**A3 精密抓放为其能力增补，2026-10-26 收束**（见 [`阶段1-点对点抓放/A3精密抓放-实验记录.md`](阶段1-点对点抓放/A3精密抓放-实验记录.md)） |
| **2 · 多类分拣** | 多类物体 + 按类放置 | 待写（进入时才写契约） | ⏸️ **暂缓** —— 2026-10-26 用户拍板「类别与泛化不做」。工具链先例（relabel/eval/live_infer + place_verify）在 tag `archive/b1a-place-view`，重启时先挑拣 |
| 3+ | 待定 —— **开工前先写任务场景**（按下面 §2 的契约六项），新技术按「解决失败模式表里哪一行」准入 | — | — |

### 当前阶段的范围界定（随阶段变）

阶段 1 覆盖单个或少量方块的点到点抓放。**不涉及** 6D 位姿估计、堆叠场景、动态目标与非立方体目标。
A3 增补覆盖：腕部相机 + 点云 + GraspNet 候选解算的**单块精密抓放**（固定朝向 ψ=0；不做类别）。

## 2. 每个阶段进入时要写一份契约

`docs/阶段/阶段N-<场景>/契约.md`，六项：
任务场景 / 与上一阶段的技术与设备差异 / 入口判据 / **出口判据** / 明确不做 / 悬案。

**出口判据要写成可执行的**（照 `scripts/board_a1.py` 的判分先例）—— 写不出可执行判据的项，不算出口。
契约**只写判据与边界**：不写工作项（→ [`../待执行命令.md`](../待执行命令.md)），不写现状（→ [`../当前状态.md`](../当前状态.md)）。
