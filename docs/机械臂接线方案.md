# 机械臂接线方案（带去和负责人讨论用）

> 2026-09-29。**这一页是讨论提纲，不是操作手册。** 深挖的证据在
> `docs/board/UR5接入方案.md` §4.5（控制链路四个 TCP 两个方向）与

>
> 现状：板端部署 7 步全完，软件侧零缺失。**真机卡在「接线」这一步** ——
> 四条线里三条是插上就完事的物理连接，只有**控制箱那根网线**需要先谈清楚。

---

## 一、先破一个概念：「连接机械臂」是**四条互不相干的线**

| # | 线 | 现状 | 缺什么 |
|---|---|---|---|
| 1 | **控制箱 ↔ Jetson**（网线） | **未接** | 一根网线 + **网段规划**（见第二节） |
| 2 | **AG-95 夹爪 ↔ Jetson**（RS485 A/B） | **未接** | **USB-RS485 适配器**（唯一必买件，¥20–100） |
| 3 | **俯视相机 ↔ Jetson**（USB 3.0） | **已接，在跑** | 无 |
| 4 | **腕部相机 ↔ Jetson**（USB） | **未接** | 线怎么走（见第四节） |

还有一根**不用管**的：机械臂本体到控制箱之间是 UR 出厂自带的专用电缆。

四条线里只有 **1 和 4 会抢那唯一的网口** —— 这是整件事的核心。

---

## 二、控制箱那根网线：物理最简单，协议最容易踩坑

### 2.1 物理层面

控制箱背面 LAN 口 → 普通 RJ45 网线 → 板子。**不需要任何特殊硬件。**

### 2.2 协议层面：链路是**双向**的

实测板载 `ur_client_library` 头文件，两个方向用的端口完全不同：

| 方向 | 谁发起 | 端口 |
|---|---|---|
| 板子 → 控制箱 | Jetson | `30004` RTDE（状态流）、`29999` Dashboard（管理命令） |
| **控制箱 → 板子** | **机械臂** | **`50001`–`50004`** |

方向二是 External Control 程序**回连**板子。头文件原话：

> *"If the robot cannot connect to this port, External Control will stop immediately."*

### 2.3 三个直接推论

1. **「能 ping 通」完全不够。** 组网要求是「控制箱能**主动**连到板子的 TCP 50001–50004」。
2. **回连的目标 IP 不是配出来的，是算出来的。** 驱动里 `reverse_ip` 默认取
   「板子连 RTDE 用的那块网卡的地址」⇒ **由路由决定**。
3. **板子和控制箱必须同网段**（同一个交换机，或直连）。跨网段指望路由器转发，
   方向一可能通、方向二默认会被 NAT / 企业防火墙挡掉 —— 而**报错会指向 URCap，
   不会指向网络**。现场最容易在这里耗掉一整天：你会去查示教器，查不出东西。

### 2.4 ⚠️ 纪律：板上的 ufw 必须保持关闭

已实测确认当前是**关**的（`grep ^ENABLED /etc/ufw/ufw.conf`）。

板子自带的 `arm-cleanup-sudo.sh` 只放行 **22 / 3389 / 5900**，**不含 50001–50004**。
谁重跑那个脚本，驱动会立刻停 —— 而症状看起来像 URCap 装错了。
**真机联调前不要重跑它。** 若合规要求必须开防火墙，补一条：

```bash
sudo ufw allow from <控制箱IP> to any port 50001:50004 proto tcp
```

## 三、网络怎么分（板上只有**一个**有线口）

实测板上只有 `eno1` 一个有线口是通的，现在挂在办公网上（DHCP）。
而**你的 SSH 也是走这个口** —— 所以「机械臂接哪」和「你怎么连上板子」会互相抢。

| 路线 | 机械臂接哪 | SSH 走哪 | 代价 |
|---|---|---|---|
| **A** 都走办公网 | 同一个办公网 | 同一个口 | 要往办公网塞一台未知设备；Dashboard `29999` 同网段谁都能连；要网管给一个 DHCP 池外的固定 IP |
| **B** 无线办公网 + 有线专供机械臂 | `eno1` 直连控制箱 | **板载无线** | **零采购**；机械臂完全不出办公室的网 |
| **C** 加 USB 网卡 | 新网卡 | `eno1` | 要买网卡（¥50–150）。**板载无线实测可用，多半不用买** |

### 3.1 ⚠️ 走 B 的话，顺序绝对不能反

你的 SSH 现在用的地址是 `eno1` 的。**一改 `eno1` 就断线。** 必须按这个顺序：

1. 打开无线并连上（`rfkill unblock wifi` → `nmcli device wifi connect …`）
2. **从第二个终端用无线地址 SSH 进去，确认真的进得来**
3. **这之后**才动 `eno1`

少了第 2 步就会把自己锁在门外。完整命令见 `待执行命令.md` 甲-13。

### 3.2 两条附带事实

- 板上的 mDNS（`avahi`）被清理脚本关了，`yahboom.local` 用不了 ⇒ 无线得配**静态 IP 或 DHCP 保留**。
- 无线够不够用？SSH、小话题没问题；**RealSense 的图/点云走无线会很难受** ⇒
  机械臂那根线必须是有线，无线只管开发链路。

## 四、两个相机：用哪一台，会决定要不要改代码

现在明确了两台都在：**臂上有腕部相机，板子上接的是俯视相机**。
这正好解开了仓库里原本的矛盾 —— `TECHNICAL_SPEC.md` §3.4 写 Eye-in-Hand，
而仿真和 `real.launch.py` 都按固定俯视实现。

而**教科书、仿真、现有代码三者一致，都是「固定俯视相机」**。教材原话：

> 「固定俯视相机」「在最顶部 1.145 米处」「保持它的位置固定非常重要，这样能保证相机外参不变」

| | 用**俯视相机** | 用**腕部相机** |
|---|---|---|
| 跟仿真结构 | **一模一样** | 完全不同 |
| 代码改动 | **零**，只要一次静态手眼标定 | 父帧 `base_link` → `tool0`；planner 要加「先走到能看见台面的位姿」；W4 的台面单应变逐帧 |
| 主要风险 | 相机被碰动后外参要重标 | 遮挡；`_select_and_approach` 是**被动等检测消息**的回调 ⇒ 臂在 HOME 时看不看得见方块成了启动前提；USB 线随臂运动 |

**建议**：第一个真机 demo 用**俯视相机**（代码零改动，真机结构与仿真对齐）；
腕部相机作为第二步的升级（近距离精定位 / 抓失败后换个角度重看）。

## 五、两台同型号 D435i 的 USB 现实

板上实测拓扑：

```
Bus 02 (10 Gbps · tegra-xusb)
  └─ 板载 4 口 hub (10 Gbps)
      └─ 俯视相机 D435i @5 Gbps  (5×uvcvideo + 1×usbhid, 720 mA)

Bus 01 (480 Mbps)
  └─ 板载 4 口 hub
      └─ 蓝牙 @12 Mbps
```

D435i 是 `bcdUSB 3.20`、`MaxPower 720mA`，跑起来要**独占一条 USB 3 链路**
（Intel 官方建议一台相机一个控制器）。两台同时跑的现实风险：

- **第二台可能协商不到 USB 3，掉到 USB 2.0（480 Mbps）** ⇒ 分辨率和帧率一起塌掉，
  realsense-viewer 会直接报 "USB 2.1 mode"。
- **UR 法兰上没有 USB 口**（e-Series 有 tool Ethernet，也没有 USB）⇒
  腕部相机的 USB 线必须**外部绑在臂上跟着动**，会影响关节活动范围，也容易被扯。

## 六、讨论提纲：问这几件事

### 网络（最要紧）

1. 控制箱现在接在哪？能不能和 Jetson 板卡**在同一个交换机 / 同一网段**？
2. 网管能不能给板子一个 **DHCP 池外的固定 IP**？
3. 板子打算放哪？（台子上 / 地上 / 控制箱旁）—— 决定网线和 USB 线要多长

### 相机

4. 腕部那台**型号是不是也是 D435i**？它的 USB 线**现在接在哪、怎么走的**？
5. 那个「**集线器**」到底是什么 —— **USB hub 还是网络交换机**？（两者对方案的含义完全不同）
6. 两台相机能不能**各占一条独立的 USB 3 链路**？

### 机械臂

7. 是 **CB3 还是 e-Series**？PolyScope 版本多少？（决定 External Control URCap 装哪个版本）
   —— **这一条到现在都还没确认**
8. 示教器上能不能配 **TCP 和负载**？（AG-95 ≈ 1 kg，不配会在动作中途保护性停机）
9. 基座固定螺栓（**M8 ×4**）在不在？（臂装台面上但不固定，碰撞风险翻倍）

### 夹爪

10. AG-95 的 **24V 电源适配器**在不在？（没它手指不初始化，整条链路走不动）
11. 能不能买一个 **USB-RS485 适配器**，并且允许**把夹爪从臂上拆下来**单独调参？

## 七、这四条线的「就绪度」

| 线 | 物理就绪 | 配置就绪 | 卡在哪 |
|---|---|---|---|
| 控制箱 ↔ Jetson | ❌ 没插网线 | ❌ 网段未定 | **要跟负责人/网管谈**（第二节） |
| AG-95 ↔ Jetson | ❌ 缺适配器 | ✅ 驱动代码已就绪（dry-run 默认开） | **采购 ¥20–100** |
| 俯视相机 ↔ Jetson | ✅ 已接 | ✅ 实测出图 | **无** |
| 腕部相机 ↔ Jetson | ❌ 没接线 | ❌ 要改代码 | **先决定用不用它**（第四节） |

**结论**：一条已经通了，两条卡在几十块钱的硬件和一次现场对话，最后一条取决于架构选择。
**没有任何一条卡在软件上。**
