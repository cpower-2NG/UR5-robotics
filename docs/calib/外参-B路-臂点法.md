# 俯视相机外参 · B 路（用臂点一下）

**目标**：`base_link ← camera_link` —— 也就是喂给 `real.launch.py` 的那组
`camera_x/y/z` + `camera_qx..qw`。

**为什么走这条而不是拿尺子量**：尺子量得到位置，量不到姿态，而俯视相机是**斜装**的
（实测光轴与台面 36.5°）。姿态错 5°，1 m 外就是 9 cm 的落点误差 ——
而 `tool0_to_fingertip` 那一整套高度参数全挂在这份外参上。
臂点法一次给出**完整的刚体变换**，且自带一个可检验的残差。

---

## 三条前置（**不做就白标**）

### 1. 示教器上先把 TCP 标了（4 点法）

这是**最容易漏、也最贵**的一条：我们记的是「尖端碰到的那一点」，
而示教器报的是**法兰**的位置。没标 TCP 的话，中间那段尖端偏移是一个**未知常数**，
它会**原样灌进外参**：

- 四个点被同一个偏移平移 ⇒ 刚体配准**吸收得掉**；
- 于是 `solve-touch` 的残差**依旧很小**，看起来一切正常，
- 而解出来的外参整体偏了一个「尖端到法兰」的距离（十几厘米量级）。

**反过来说这也是白赚**：TCP 标完，`grasp_planner.yaml` 里
`tool0_to_fingertip`（D44，现在还是 Robotiq 2F-85 的推导值 `0.13`）
也顺手有真值了。

用**一个尖点**（笔尖、探针、或夹爪指尖的角）做 TCP，不要用平面。
标完用第 5 点做一次**验证**，示教器会给误差；超过 1 mm 就重标。

### 2. 顺带把负载/重心配了

AG-95 约 1 kg、离法兰 0.13 m+。驱动的 `safety_limits` 默认**开**
（`safety_k_position=20`），没配负载会在动作中途**保护性停机**。
今晚这一步不做也行（今天不动臂），但明天动作前必须有。

### 3. 靶纸压平、贴牢、**全程不许被碰动**

四个碰点必须落在**同一个平面**上。靶纸在标定过程中被推动哪怕一点，
解出来的就是个歪的平面 —— 残差会涨，但**涨多少取决于推了多少**，别指望它报警。

A4 那张（9×12 格 / 20 mm）就是手边这张，**够用**，不用另印 A3。

---

## ⚠️ 安全

第 ② 步是**真机运动**（手动/示教器点动推臂）。执行前需要：

- 你**当次明确授权**；
- **急停在手边**；
- 工作区隔离（人别站在臂的行程里）；
- 速度滑条压到最低。

第 ⓪①③ 步**完全不动臂**，可以先做、随时做。

## ⓪ 抓一帧俯视图 + 内参（不动臂）

在**板子**上跑（要 ROS 环境）。相机得先起着：

```bash
source /opt/ros/humble/setup.bash
python3 scripts/board_extrinsics.py capture --out-dir /tmp/topcam
```

默认话题 `/camera/color/...`，对应 `config/realsense_camera.yaml` 里
**钉死的那台俯视相机**（SDK 号 `<topcam-serial>`）。

产出 `frame.png` + `info.json`。它会打印 `frame_id` 和 fx/fy/cx/cy ——
**记下 frame_id**，这份外参是相对那个光学帧的。

> 如果报「没收到帧」，先看它逐路打出来的「收到第一帧 ...」：
> **三路全没来**多半是 DDS 发现（DOMAIN_ID / 网络），
> **只缺一路**是那一路话题自己的问题。这两种查法完全不同。

## ① 相机 ← 靶（不动臂）

```bash
python3 scripts/board_extrinsics.py pnp \
    --image /tmp/topcam/frame.png --info /tmp/topcam/info.json \
    --square-mm 20 --cols 9 --rows 12
```

**判据：重投影误差中位 < 1 px 才用。** 超了先查靶平不平、图糊不糊、有没有反光。

> ⚠️ **重投影误差**不校验尺度**。** 它只校验姿态**形状**。
> 实测（第五十八轮）：故意用一个偏小 **1.2%** 的内参去解，重投影仍然只有
> **0.03 px**（最大 0.14 px），而解出的距离**正好偏 1.2%**。
> 所以这一关过了，**不代表**尺度是对的 —— 后面第 3 条交叉验证就是补它的。

顺手核一个数：输出的 `|t|` 是「相机到靶原点」的距离，按已知几何应当在
**1.1 m 上下**（相机在台面上方 0.653 m、与台面 36.5° ⇒ 0.653 / sin 36.5° ≈ 1.10）。
差得远就是内参或图案尺寸不对。

> **这条链已知整体偏 ~1.2%**（棋盘格靶已用卡尺验证过是准的，见 `README.md`）。
> 所以 `|t|` 比预期**大 1.2% 左右是预期内的**，不是新问题。
> 那 1.2% 到底是深度尺度还是内参，**平面靶分不开** ——
> 明天顺手用皮尺量一下相机到台面的高度（和 0.653 m 比）就能定案。

> `--cols/--rows` 是**方格数**（A4 那张 9×12 格就传 9 和 12）。
> ⚠️ 与 `measure_board_scale.py` 的 `--cols/--rows` **约定相反** ——
> 那边传**内角点数**（同一张靶是 8 和 11）。同一个板子两组数，别串。

## ② base ← 靶：碰点（**真机运动**）

靶系原点 = 靶面**外角点**（第一格的角），平面是 z=0。
A4 那张 20 mm / 9×12 格的四个外角点在靶系里是：

| 点 | 靶系坐标 (mm) |
|---|---|
| ① 左下 | **(0, 0)** |
| ② 右下 | **(180, 0)** |
| ③ 右上 | **(180, 240)** |
| ④ 左上 | **(0, 240)** |

用标定好的 TCP 尖点，**逐个碰到这四个角**，每个点从示教器上读出 base 系坐标。

**再加四个内角点更好**（八个点比四个点抗碰点噪声），它们的靶系坐标是：

| 点 | 靶系坐标 (mm) |
|---|---|
| ⑤ | **(20, 20)** |
| ⑥ | **(160, 20)** |
| ⑦ | **(160, 220)** |
| ⑧ | **(20, 220)** |

> ④ 个外角点**是非共线的**，所以四个就足以定出刚体，不会退化。
> 加内点只是把碰点噪声平均掉 —— 不是必需，是更稳。

**碰的时候注意**：

- 每次**用同样的「刚碰到」力度**。压深了，尖端会侧滑，而且四点不共面；
- 四个点必须落在**靶纸的上表面**（就是印着图案那个面）；
- 顺序随意，但**靶纸不许动**。

写成 `points.json`（**单位必须写出来**，示教器上读出来通常是毫米）：

```json
{
  "unit": "mm",
  "R_board_pts": [[0,0,0],[180,0,0],[180,240,0],[0,240,0],
                  [20,20,0],[160,20,0],[160,220,0],[20,220,0]],
  "P_base_pts": [[...], [...], [...], [...], [...], [...], [...], [...]]
}
```

## ③ 解算 + 合成

```bash
python3 scripts/board_extrinsics.py solve-touch --points points.json
python3 scripts/board_extrinsics.py compose \
    --base-from-board base_from_board.json \
    --cam-from-board  cam_from_board.json
```

**判据：`solve-touch` 的 RMS < 3 mm。** 超了它会把要查的三样列出来
（TCP 标没标 / 是不是顶住了同一个物理点 / 靶有没有被推动）。

`compose` 会打印**可以直接粘进 `real.launch.py`** 的那几行，
并自检一次「相机离基座多远、多高」是否讲得通。

## 怎么知道标对了（三条独立交叉验证）

1. **重投影 < 1 px**（①）—— 相机侧自洽。
2. **碰点 RMS < 3 mm**（③）—— 臂侧自洽。
3. **`compose` 打出的相机高度**，应当接近**实测的 0.653 m**
   （第五十六轮用深度直接量的台面到相机高度）。两者独立，
   对得上就基本可以信了 —— 差得多，最可能是靶的尺度（方格真值）
   或 TCP 有问题。

> **再补一条真正的米制真值（皮尺，一分钟）**：量一次**相机到台面**的距离。
> 这是唯一能把「深度尺度错」和「内参错」分开的量 —— 上面三条都做不到
> （第三条用的是**深度算出来的** 0.653 m，它本身就带着那 1.2%）。
> 皮尺读数与 0.653 m 差 ~1.2%（≈8 mm）⇒ 深度尺度；对得上 ⇒ 内参。

> 还有一条更强的第二意见（**以后做**）：同一帧里同时走
> 「PnP 靶→相机」和「单应 靶面→像素」两条路，两者对得上就是独立的确认。

## 已知的坑（都是已经踩过的）

| 坑 | 后果 | 防法 |
|---|---|---|
| **没标 TCP** | 尖端偏移灌进外参，**残差看不出来** | 前置 1 |
| **单位混用** | 整体差 1000 倍，**全程不报错** | 文件里写 `"unit"`；`compose` 会拦 |
| **`--cols/--rows` 传了内角点数** | 找不到角点，或长短边对调、外参错得离谱 | 这个脚本传**方格数** |
| **靶在画面里转了 90°** | 非正方图案**不是旋转不变**的，一个角点都找不到 | 脚本两种朝向都试 |
| **靶纸翘/被推动** | 四点不共面，解出歪平面 | 前置 3 |
| **内参手抄错** | 外参整体歪，重投影照样好看 | 用 `capture` 机器转写 |
