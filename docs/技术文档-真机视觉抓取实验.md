## 1. 这个实验做什么

**让一台装在桌面上的 UR5，用俯视相机看见桌上的方块，自己规划并抓起来，放到指定槽位。**

一句话链路：**看得见 → 算得出在哪 → 够得到且不撞桌 → 抓得住 → 放得下**。

范围：
- **做**：单个/少量方块的点到点抓放（检测 → 3D 定位 → IK → 轨迹 → 夹爪闭合 → 搬运 → 放置 → 收工）。
- **不做**：6D 位姿估计、杂乱堆叠、动态抓取、非立方体。

已完成的一次实跑（2026-10-03）：**抓 1 放 1，收工干净**。

## 3. 数据流

```
D435i(俯视) ──/camera/color/image_raw──┐
             ──/camera/color/camera_info┤
             ──/camera/aligned_depth_to_color/image_raw
                                        ▼
                            yolo_detector/detector_node
                                        │ /detections（**像素**坐标）
                                        ▼
                    perception_3d/projector_node   ← 唯一投影点
                      像素 + 深度 ──tf2──▶ base_link
                                        │ /targets_3d
                                        ▼
                    grasp_planner/planner_node
                      选区(in_zone) ─ IK(/compute_ik) ─ 整段护栏
                                        │ FollowJointTrajectory
                                        ▼
              /scaled_joint_trajectory_controller  ← **尊重示教器速度滑条**
                                        ▼
                            ur_robot_driver（RTDE）
                                        ▼
                                       UR5

夹爪：planner_node ──pymodbus(串口)──▶ AG-95        ← 完全独立的一条链
```

三条要点：

1. **投影只有一处**（`projector_node`）。在线推理与离线标注必须用它那条链的**严格逆运算**，否则「训练标签和推理用的不是同一套数学」。
2. **规划器不做投影**，它只消费 `base_link` 下的 `/targets_3d`。
3. **规划器不走 `/move_action`**：它只用 `/compute_ik` 解位姿，轨迹**直接发给 JTC**。所以 MoveIt 的规划场景里没有桌子也不影响，但**也意味着 `avoid_collisions=True` 防不了桌子** —— 挡撞桌的是**肘高护栏**（§6.3）。

## 4. 坐标系与约定 ⚠️ 这一章最贵

### 4.1 `base_link` 与 `base` 差 **180° 绕 z**（最容易致命的一条）

UR 的 URDF 里，机器人自己的 `base` 帧与 `base_link` **不是同一个帧**：

```
$ ros2 run tf2_ros tf2_echo base_link base
  Translation: [0, 0, 0]
  Rotation in RPY (degree) [0, 0, 180.000]
```

后果分两种，都对得上：

| 你在哪儿用 | 后果 |
|---|---|
| **示教器**读位置 / `tcp_pose_broadcaster` | 报的是 **`base`** 帧 |
| **MoveIt** 的 `/compute_ik`、`/compute_fk` | 算的是 **`base_link`** |

⇒ **拿示教器读来的坐标直接当 `base_link` 用，机械臂会跑到关于基座对称的那个点上去**
（x、y 同时取反）。实跑验证：同一个目标，MoveIt 说 tool0 在 `(-0.42,-0.50,+0.19)`，
而机器人自报 TCP 是 `(+0.42,+0.50,-0.01)`。

**手眼标定是用碰点做的**（碰点位置从示教器读）⇒ 标定结果天然在 **`base`** 帧。
要把它当 `base_link ← camera_link` 用，必须先左乘 `Rz(π)`：

```
R' = Rz(π) · R          t' = Rz(π) · t          Rz(π) = diag(-1, -1, 1)
```

**判据**：改完之后，同一个物体报出来的 `base_link` 坐标应该正好是原来的 x、y 取反。
另外「光轴与台面法线的夹角」不该变（这是个纯 z 旋转）—— 实测两侧都是 35.73°。

### 4.2 `camera_link` 与光学系

- `camera_link`：x 前、y 左、z 上（ROS 常规）
- `camera_color_optical_frame`：z 前、x 右、y 下（针孔投影要的是这个）

固定旋转（三个轴在 link 系里的表示）：`opt_x = −link_y`、`opt_y = −link_z`、`opt_z = link_x`。

⚠️ 「光轴」是 **`camera_link` 的 +x**（不是 +z）。投影时用错轴会算出一个看着像样、其实整个歪掉的结果。

### 4.3 `tool0` 与示教器 TCP

- MoveIt / URDF 的 `tool0` = **法兰**。
- 示教器上配的 TCP = 从法兰沿工具 z 再偏移（本项目 `0/0/200.2` mm，为的是让「碰台面读到 0」）。
- 两者差一个**标量偏置**（z 方向 0.2 m），**x/y 不受影响** —— 所以别拿这个差去解释 x/y 的异常。

### 4.4 高度语义：`wz` 是**顶面**

`perception_3d` 报出来的 `wz` 是**方块可见顶面**（俯视深度看到的就是顶面），不是中心。
⇒ `pick_zone` 的 z 区间、`place_z` 全部按「**台面 + 方块高**」算：

```
top    = table_z + block_height
pick_zone 的 z ≈ [top − pad, top + pad]        （pad 默认 0.02）
place_z       = top
```

⚠️ 按「中心」算会差**半个方块**，而症状是「IK 全部被拒、能抓不能放」这种极难倒推的现象。

## 5. 参数体系：三层，谁覆盖谁必须清楚

| 层 | 文件/来源 | 说明 |
|---|---|---|
| ① 包内默认 | `grasp_planner/config/grasp_planner.yaml` | 全部参数的定义处（56 项） |
| ② 现场覆盖 | `planner_params_file:=<你的 yaml>` | ⚠️ **是替换不是叠加** |
| ③ launch 覆盖 | `pipeline.launch.py` 按 `camera_source` 派生 | 见下 |

**② 是替换**：launch 里写的是 `parameters=[<该文件>, {覆盖项}]` —— 包内那份**不再加载**。
所以现场 yaml **必须完整**，漏掉的键会退回节点里 `declare_parameter` 的硬编码默认值
（那些是按仿真几何写的）。

**③ 由 launch 覆盖、写在 yaml 里也不生效的键**：

```
ik_group · trajectory_action · tool0_to_fingertip · place_release_lift
gripper_backend · table_scene_enabled · carry_objects
```

它们**随后端变**（仿真值是另一套），所以由 launch 按 `camera_source` 派生，
且 driver 与 move_group 必须拿到**同一个值**（否则两边是两套几何、都不报错）。

**现场 yaml 真正要改的**（按本项目实测）：

```yaml
table_plane_z: 0.0                       # 臂直接装在桌面上 ⇒ 台面就在 base 的 z≈0
pick_zone:  [0.40, 0.60, 0.00, 0.50, 0.000, 0.0485]
place_slots: [0.45,-0.25, 0.55,-0.25, 0.45,-0.35, 0.55,-0.35]
place_z: 0.0285                          # = 台面 + 方块高（顶面）
ag95_dry_run: false                      # ⚠️ 默认 true ⇒ 夹爪只打日志、不动手指
```

`place_slots` 的三条硬约束（启动期检查）：
1. **必须在 `pick_zone` 之外** —— 硬错误。这就是终止机制本身。
2. 间距 ≥ 夹爪行程（AG-95 = 95 mm）—— 告警。
3. 扁平 `x,y,x,y,...`（ROS 2 没有嵌套数组，写成 `[[x,y],…]` 节点起不来）。

## 6. 标准全流程

### 阶段 0 · 板子准备

- `ros-humble-moveit`（15 个子包）
- `usermod -aG dialout jetson`（否则 `/dev/ttyUSB0` 打不开）
- `pymodbus`（3.15）
- 内存：停掉 ollama 与桌面（8 GB 板子跑 MoveIt + 驱动 + YOLO 很紧）

### 阶段 1 · 示教器三件事

| # | 做什么 | 为什么 |
|---|---|---|
| 1 | 标/填 **TCP** | 碰点法读的是**尖端**，示教器报的是**法兰**；没标 TCP 会把尖端偏移原样灌进外参 |
| 2 | 配 **负载 / 重心** | 没配可能在动作中途**保护性停机**（这是 URControl 自己的要求，与 `safety_limits` 无关） |
| 3 | `Installation → External Control`：**Host IP = 上位机在控制箱那个网段的地址**，端口 `50002` 不动 | URCap 靠这个地址回来取脚本 |

> 端口**别改成 50001**：50002 是「机器人 → 上位机取脚本」，50004 是 reverse interface，各司其职。

### 阶段 2 · 起驱动 → 播放 URCap（**次序不能反**）

```bash
ros2 launch yolo_bringup real.launch.py robot_ip:=<控制箱IP> ur_type:=ur5 \
    start_pipeline:=false publish_camera_tf:=false gripper_backend:=none \
    carry_objects:=false safety_limits:=true
```

**先起驱动，再去示教器按播放。** 反了的话，机器人连 `50002` 会被拒
（「连接被拒绝」而不是超时 ⇒ 地址是对的、只是没人接）。

播放成功后驱动日志会出现：

```
[UR_Client_Library:]: Robot requested program
[UR_Client_Library:]: Sent program to robot
[UR_Client_Library:]: Robot connected to reverse interface. Ready to receive control commands.
[URPositionHardwareInterface]: Calibration checked successfully.
```

**逐项核对**（全只读）：
`/joint_states` 有真值 · `scaled_joint_trajectory_controller` **active** ·
`/compute_ik` `/compute_fk` 在 · `robotmode: RUNNING` · `safetystatus: NORMAL` · `programState: PLAYING`

### 阶段 3 · 手眼标定 + **漂移判据**

标定走「碰点法」：拍一张靶纸得 `cam←board`，用臂碰靶纸若干角点得 `base←board`，复合成 `base←camera`。
产出 `extrinsics-*.json`（含 `rms_touch_m`、`reproj_px` 两个可检验的残差）。

⚠️ **俯视外参会无声过期**（实测一天 0.945°），而老式判据会**静默放行**。所以：

```bash
python3 scripts/topcam_drift_check.py --old <外参据以算出的那帧> --new <刚抓的帧> \
    --info <新帧的 info.json>
# 0 = 外参还有效；1 = 作废，重跑标定
```

它量的是**全幅光流**：整幅一起动 ⇒ 相机动了；只有局部动 ⇒ 是那个东西被碰了。
⚠️ 场景里必须有可追踪的特征 —— **光板白台面上判不了**（会报「特征点太少」）。

### 阶段 4 · 包线扫描 → 划区

**为什么必须做**：`avoid_collisions=True` 防不了桌子（桌子不在规划场景里），挡撞桌的只有肘高护栏。
包线把「跑一遍看看」变成「照着划区」。

```bash
python3 scripts/table_safety_envelope.py --table-z 0.0 --retry-seed home \
    --x-min 0.15 --x-max 0.95 --y-min -0.50 --y-max 0.50 --step 0.05 --json /tmp/env.json
```

扫的是**每一个桌面格 × 四个 tool0 高度**，用 `/compute_ik` + `/compute_fk` 判
`forearm_link` / `wrist_1_link` 的原点是否低于 `table_z + guard_margin`。
产出：**撞桌格**（躲开）· **够不到**（框到这儿白框）· **最大全安全矩形**（照抄这个）。

⚠️ 三条要记住：
1. **逐格分类不可复现**（同一位姿连问会回来不同的肘分支）⇒ **离边界至少留一格（0.05 m）**，
   而上面那块**矩形**是稳的。
2. 判据只看**连杆原点高度**，不含连杆/夹爪**本体半径**，也不含**相机视野**。
3. **区的矩形必须落在「几何安全 ∩ 相机看得见 ∩ 真会往那儿放东西」的交集里。**

### 阶段 5 · 现场 yaml

见 §5。**先只写不改**，起一次确认它真的生效：

```bash
ros2 param get /grasp_planner pick_zone     # 必须回你写的值
```

### 阶段 6 · 夹爪初始化（AG-95）

**AG-95 断电就丢初始化**，而未初始化时的失效是**静默**的：位置回读恒 0 ⇒ `close()`
「写目标 0 → 回读 0 → 与目标相符」⇒ 报成功，而手指一步没动、**一条日志都没有**。

```bash
python3 scripts/ag95_init_close.py              # 只读预演，一个寄存器都不写
python3 scripts/ag95_init_close.py --go         # 真初始化（两指走全行程自检）
```

### 阶段 7 · 逐级验证（**这一级一级是纪律，不是建议**）

| 级 | 做什么 | 判据 |
|---|---|---|
| ① 只读 | 驱动起来、`/joint_states` 有数、`/compute_ik` 可用、`/targets_3d` 数值合理 | 见阶段 2 |
| ② 感知单跑 | `skip_planner:=true` 起感知，读 `/targets_3d` | **方块必须真的落在 `pick_zone` 里**（三轴都查；不落就一条都进不来，而那是**静默**的） |
| ③ 小运动 | 夹爪一次开合 + 单关节 ±5°、动完回原位 | `status==SUCCEEDED` **且** `error_code==0` |
| ④ 完整抓取 | 放开规划器 | 见 §8 |

## 7. 开发机上的仿真（与真机的关系）

仿真**只在开发机（WSL）** 上跑 —— Orin 上没有 Gazebo。配方是**三处 source + 一次叠加**：

```bash
source /opt/ros/humble/setup.bash
source <gz_ros2_control 所在 ws>/install/setup.bash     # 必须 GZ_VERSION=harmonic 编译
source ros2_ws/install/setup.bash
export PYTHONPATH=<venv>/lib/python3.10/site-packages:$PYTHONPATH   # torch/ultralytics
ros2 launch arm_grasp_sim full.launch.py headless:=true
```

- `rclpy` 在 ROS 里、`torch` 在 venv 里，两者互不可见，**运行**时叠起来用；
  **构建**要用纯净环境（叠了 venv 之后 `colcon build` 会因 setuptools 版本而失败）。
- 仿真场景**不是**真机几何（台面在 `base_link` z≈−0.39，方块在 +x）。
  它的价值是**验证状态机与运动控制**，不是验证位置。要看位置必须看真机。

## 8. 一次完整抓取：期望的日志

```
AG-95 **真实写入已启用**（ag95_dry_run:=false）      ← ERROR 级告示，设计如此
抓取区 x[...] y[...] z[...] | 放置槽位 N 个 @ place_z=...
初始化：先张开夹爪，再回 HOME ...
候选 K 个 ['block', ...] | 已放置 0/N | 已抓 0 个 | 连续未放置 0/10
→ 选中 [block] score=... base_link=(x, y, z)
  接近解：['...', ...]
接近完成 —— 下降到抓取高度
下降完成 —— 闭合夹爪
[WARN] AG-95 等手指到位超时（目标 0.0 mm，最后回读 X mm）   ← **成功信号**
已夹住物体（回读位置=X）—— 抬起
抬起成功，已记录 base_link=(x,y,z)（累计 1 个）
返回 HOME ... → 已到 HOME —— 去放置位[i] (x, y)
放置位接近完成 —— 下降到 place_z=...
已到放置高度 —— 张开夹爪放下
已放置 1/N 个 → 返回 HOME ...
收工：空闲 20s 没有发起过任何一次抓取尝试
```

### 8.1 夹爪回读值读法（**一条判据三种结论**）

| 回读 | 含义 |
|---|---|
| **≈ 全开（如 95 mm）** | 手指**一步没动** ⇒ 没写进去（dry-run / 未初始化 / 串口） |
| **0 mm** | 走到闭合位 ⇒ **空夹**（中间没东西挡） |
| **中间值（如 35 mm）** | **夹着东西** —— 到不了 0 正是被方块挡住 |

所以那条 `WARN` 在中间值出现时是**成功**，不是故障。

### 8.2 三种收工路径

| 触发 | 日志 |
|---|---|
| 抓取区空了 | `空闲 Ns 没有发起过任何一次抓取尝试` |
| 槽位用尽 | `收工：放置槽位已用尽（N 个）—— 没有地方可放了` |
| 连续无进展 | `连续未放置 M/10`（`max_attempts_without_place`） |

## 9. AG-95 寄存器表

| 寄存器 | 读/写 | 含义 |
|---|---|---|
| `0x0100` | **只写** | 初始化**命令**（写 `0x01` 单向 / `0xA5` 全行程）—— ⚠️ **读回恒 0**，拿它判状态从来没生效过 |
| `0x0101` | 写 | 力（45~160 N） |
| `0x0103` | 写 | 目标位置（0–1000 千分位）—— 读回来是「上次命令到哪」 |
| **`0x0200`** | **只读** | **初始化状态：0 = 未初始化 / 2 = 正在初始化 / 1 = 已完成** |
| `0x0201` | 只读 | 到位状态 |
| `0x0202` | 只读 | 实时位置（0–1000 千分位）：**0 = 全闭，1000 = 全开** |

**写位置之前必须先读 `0x0200` 并确认等于 1** —— 0 和 2 都要**拒绝**（见 §6 阶段 6 的静默失效）。
`gripper.py` 已经这么做（闸门放在 **dry-run 早返回之后** —— dry-run 的契约是「从站零流量」）。

⚠️ **初始化是一次全行程自检**（张开**和**合拢都走）。所以给 `--go` 之前要确认
**两指整个行程范围内都是空的**，不是「指间放开就行」。

⚠️ 「读回一个值」≠「这个寄存器存在」：该从站对不存在的地址也回 0。判据要挑**读到过非 0 值**的地址。

## 12. 故障速查

| 症状 | 先查 |
|---|---|
| 示教器按播放报「连接被拒绝」 | 驱动起了吗（`ss -lntp \| grep 5000`）？**次序是先驱动、后播放** |
| 机械臂跑到关于基座对称的位置 | 相机外参的父帧是不是 `base` 被当成了 `base_link`（§4.1） |
| 夹爪一动不动、回读一直是全开 | `ag95_dry_run` 是不是 true？`0x0200` 是不是 1？ |
| 夹爪"报成功"但没动 | 未初始化 + 位置回读恒 0 的静默失效（§9） |
| 规划器一条动作都不做、日志里什么都没有 | 方块没落进 `pick_zone`（`in_zone` 是**静默** `continue`） |
| 能抓不能放（IK 全被拒） | `place_z` 是不是按「中心」而不是「顶面」算的（§4.4） |
| 包线扫出「一个位姿都没解出来」 | 少了 `robot_state_publisher`（用 `no_arm_stack.py`，别单起 `start_ur_driver:=false`） |
| `ros2 topic list` / `action list` 空或超时 | CLI 的 daemon 毛病 —— 加 `--no-daemon` 或给足时间；**别当成链路断了** |
| 改 yaml 没反应 | 起节点的那个 launch 到底加载了哪份 yaml（§5） |
