## 0. 先纠三条

1. **`arm-ready.sh` 里的风扇拉满是无效的**。板子上 `nvfancontrol.service`（PID 766）在跑闭环温控，2 秒轮询一次。脚本写 `pwm1=255` 后，几秒内就被它改回 131（约 51% 占空比）。你听到的"风扇猛转一下"就是这几秒。温度实测 48–55 ℃，本来就健康，不需要拉满。

## 3. UR5 后续怎么接（和之前会话的说法不同，请以此为准）

### 3.1 先纠正一个方向性错误

**UR5 不走 USB 串口。** 它是**网口设备**，靠标准以太网通信（Dashboard 29999、Primary 30001/30002、RTDE 30004 等）。`~/CH341SER`、`/dev/ttyUSB*` 这些和 UR5 无关，那是给 CH340 类串口外设的。

所以 `arm-check.sh` 里"检查 `/dev/ttyUSB*` 判断机械臂"这段对 UR5 无效，应该改成**网络连通性检查**（ping 机器人 + 探测 29999/30004 端口）。

### 3.2 网络怎么接（两个方案，推荐前者）

当前 `eno1` 只有一个地址 `<host-ip>/23`（办公网），**没有任何路由能到 `<ip>/24`**，所以机器人放在 `192.168.10.x` 的话现在根本连不上。

**方案 A（推荐）：加一块 USB 3.0 千兆网卡做专用控制网**
- 板子上有 USB 3.0 口（当前接着一个 VIA USB3.1 Hub），插一块几十元的 USB 千兆网卡，起一个独立接口。
- 该接口静态配 `<ip>/24`，机器人配 `<ip>/24`，**机器人侧网关留空**（防止它跑去连外网）。
- 好处：控制流量完全不经过办公网，广播/组播不会污染办公网，DDS 发现稳定，也符合你要的"资源隔离"。

**方案 B（省钱）：在 `eno1` 上加第二个 IP**
```bash
sudo nmcli con mod "Wired connection 1" +ipv4.addresses <ip>/24
sudo nmcli con up "Wired connection 1"
```
- 一条网线同时跑办公网和机器人网。能用，但机器人流量和办公网混在同一张网卡上，排障和隔离都差一些。

### 3.3 接入步骤（网络通了以后）

1. **确认型号和固件**：UR5 分 CB3(UR5) 和 e 系列(UR5e)，驱动参数不同（`ur_type:=ur5` / `ur5e`）。在示教器 `设置 → 网络` 里看并固定机器人 IP。
2. **装 ROS 2 驱动**（当前**完全没装**，只有 URDF 解析库）：
   ```bash
   sudo apt install ros-humble-ur ros-humble-ur-msgs
   ```
   （这版是 UR 官方的 `ur_robot_driver`，Humble 有二进制包；装不上再从源码编译）
3. **示教器上装 External Control URCap**，建一个程序只放 `External Control` 节点并设为开机自动加载；机器人切到 **Remote Control** 模式。
4. **启动驱动**：
   ```bash
   ros2 launch ur_robot_driver ur_control.launch.py ur_type:=ur5 robot_ip:=<ip>
   ```
   MoveIt 规划再加 `ur_moveit_config`。
5. **标定**：`ros2 launch ur_calibration calibration_correction.launch.py robot_ip:=<ip>`，把生成的标定文件放进驱动配置。
6. **验证**：`ros2 topic hz /joint_states`（应在 125 Hz 附近）、`ros2 control list_controllers`。
7. **DDS 优化**：`ROS_DOMAIN_ID=99` 你已经全局设好了。建议固定 `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp` 并配一份绑定控制网卡的 CycloneDDS XML，避免 DDS 广播跑到办公网上。

### 3.4 实时性预期（说实话）

当前是 **PREEMPT 非 RT 内核**（`CONFIG_HZ=250`）。UR 的伺服环在控制器内部跑（500 Hz 硬件级），上位机通过 RTDE 发指令：

| 上位机下发频率 | 周期 | 这个内核能不能扛 |
|---|---|---|
| 125 Hz | 8 ms | 可以，MoveIt + ur_robot_driver 的常规用法 |
| 500 Hz | 2 ms | 抖动风险高，必须配合 CPU 独占 + performance 调频 |

要做真正的硬实时才需要 RT 内核，Jetson 平台对 RT 内核支持有限，一般不建议为这个折腾。

## 4. 资源隔离怎么做

### 4.1 现状

- 用户会话 `user.slice` = **6.0 GB / 7.4 GB**，系统服务仅 0.58 GB。
- CPU 调度器已是 `performance`，6 核全锁 `1984 MHz`（脚本生效，`arm-cpufreq.service` 已 enable）。
- cgroup v2 已启用，`cpuset cpu io memory hugetlb pids` 控制器都在 —— **具备做隔离的条件**。
- 透明大页：**`always`**（对控制环有抖动影响，值得改）。
- swap：zram 优先级 `5`、磁盘 swap 文件 `-2`。内核是**优先级高的先用**，所以 zram 已经优先、顺序是对的；需要动的只是把 8 G 的 swap 文件瘦身，并且 `/etc/fstab` 里同一行重复写了三次，可以顺手收敛。

### 4.2 建议的隔离分层

| 层 | 做什么 | 手段 |
|---|---|---|
| CPU 核隔离 | 把控制环固定到专用核，桌面/浏览器赶到 0-1 号核 | `arm-control.slice` 加 `CPUAffinity=4-5`；用户会话加 `CPUAffinity=0-1` + `CPUQuota` |
| 内存保底 | 给控制栈留 1 G 不被抢 | 切片 `MemoryMin=1G`，用户会话 `MemoryMax=4G` |
| IO 优先级 | 控制节点读写优先 | 切片 `IOWeight=1000` |
| 硬隔离（可选） | 内核层面把 2 个核从调度器摘出去 | 内核 cmdline `isolcpus=4,5 nohz_full=4,5 rcu_nocbs=4,5`（需重启，Orin 上可用） |
| 页表抖动 | 关掉透明大页的自动合并 | THP `always → madvise`（保守）或 `never`（激进），做成开机持久 |
| 交换抖动 | 让 zram 先用、磁盘 swap 靠后 | 顺序本已正确（zram 5 > 文件 -2）；只需把 8 G swap 文件缩到 2 G，并清掉 fstab 重复行 |
| 运行时 | 控制节点自己跑在切片里 | `systemd-run --slice=arm-control.slice -p CPUAffinity=4-5 --pty bash` |

### 4.3 `arm-ready.sh` 的两个 bug（顺带修）

```bash
# bug 1：把 kHz 原样当 MHz 打印（你看到的 "1984000 MHz"）
echo "CPU 最大频: $(cat .../scaling_max_freq 2>/dev/null / 1000 | head -1) MHz"

# bug 2：xargs + bash -c 的 $0/$1 错位，参数落到了 $0，$1 是空
#        → 你看到的 "syntax error: operand expected ... 50125: line 1"
cat .../thermal_zone0/temp | xargs -r bash -c 'echo $((($1/1000)))'
```

修正写法：

```bash
echo "CPU 最大频: $(( $(cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_max_freq) / 1000 )) MHz"
t=$(cat /sys/class/thermal/thermal_zone0/temp 2>/dev/null)
[ -n "$t" ] && echo "温度(C): cpu=$((t/1000))"
```

并且**建议删掉"风扇拉满"那一步** —— 它会被 `nvfancontrol` 在 2 秒内覆盖，只是白响一阵。温度 48–55 ℃，闭环温控本来就在正常工作。
