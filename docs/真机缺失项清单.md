**优先级**：**1（RS485 适配器）是唯一必买的**；3（标定板）自制即可；
**2（网卡）2026-09-30 实测通过 ⇒ 正式划掉，不用买**。

**为什么网卡可以取消**：板上实测**有可用的无线网卡**（RTL8822CE，驱动已加载，
只是被 `rfkill` 软禁用）⇒ 用**无线**走办公网（SSH / 开发链路）、**有线网口**
（`eno1`）专供机械臂，就同时拿到了方案 B 的隔离和不断的 SSH，**零采购**。
**2026-09-30 已实测走通**：用户拔掉网线 → 无线成为唯一默认路由 → 开发机经
`<board-ip>` SSH 直接连上（`hostname` → `yahboom`），外网 TCP 通，
板子→开发机吞吐 **7.1 MB/s**（有线实测 7.4 MB/s）。全过程与判据见
`docs/待执行命令.md` 的 **甲-23**（现已完成）。
实测证据与安全操作顺序见同文件的 **甲-13**（⚠️ 顺序不能反：必须**先**确认能经
无线 SSH 进来，**再**改有线口，否则会把自己锁在门外 —— 而「确认」这一步要先按
甲-23 把有线默认路由去掉，否则经无线地址的 SSH **结构上不可能通**）。

**两条零采购路线的区别**（都可选，按你们对隔离的要求）：

| | 方案 A：都走办公网 | **方案 B-改：无线办公网 + 有线专供机械臂** |
|---|---|---|
| 硬件 | 零 | **零**（用板载无线） |
| 需要网管 | 给一个 DHCP 池外静态 IP | 不需要（机械臂完全不出办公室的网） |
| 机械臂暴露在办公网 | **是**（Dashboard 29999 可被同网段访问） | **否** |
| SSH/开发链路 | 与机械臂共用一根线 | 走无线，与机械臂**物理隔离** |

## 二·五、网络要求（不花钱，但要跟网管说清；**接 UR5 前必读**）

UR 驱动的链路**是双向的**，这一点决定了组网要求 —— 「板子能 ping 通控制箱」**不够**：

| 方向 | 谁发起 | 端口 | 说明 |
|---|---|---|---|
| 板子 → 控制箱 | Jetson | **30004** RTDE、**29999** Dashboard | 状态流 + 管理命令，出站 |
| **控制箱 → 板子** | **机械臂** | **50001–50004** | External Control 程序**回连**板子；被挡 ⇒ 驱动头文件原话 *"External Control will stop immediately"* |

⇒ **给网管/IT 的一句话**：*机械臂控制箱需要能和 Jetson 板卡**在同一网段**（L2 直达），
或至少保证控制箱能**主动连到板卡的 TCP 50001–50004**。*

三个具体后果：

1. **方案 A（办公网）要的是「同网段 + 一个 DHCP 池外的静态 IP」** —— 这是最省事的
   路线，**零采购**，需要网管配合的就是这两件事（外加确认交换机没有 802.1X/端口安全
   挡住控制箱这个未知设备）。
2. **不要把控制箱放在另一个网段指望路由器转发**：方向一可能通，方向二（回连）默认
   被 NAT / 企业防火墙挡住，而报错会指向 URCap，不会指向网络。详见
   `board/UR5接入方案.md` §4.5。
3. **板上的 ufw 别开**（已确认当前是关的）：`arm-cleanup-sudo.sh` 只放行
   22/3389/5900，**不含** 50001–50004 ⇒ 开了就挡死回连。真机联调前
   **不要重跑那个脚本**；若合规要求必须开，补
   `sudo ufw allow from <控制箱IP> to any port 50001:50004 proto tcp`。

> 所以第二节的 **USB 网卡**真正的价值是 **隔离** + **给板子第二个网口**（板上只有
> `eno1` 一个有线口，单口走独立网段会把 SSH/开发链路一起切断）—— **不是**为了让
> UR 连得上。
