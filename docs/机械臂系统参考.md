> ### 🔴 认相机**只认外壳标签上的 SDK 号**。
> RealSense 有**两个**序列号：USB 描述符里的 **ASIC 号**（挂在 `idVendor=8086` 的
> sysfs 里）和相机 flash 里、**印在外壳标签上**的 **SDK 号**。两者不同。
> 上面两台的 ASIC 号是 `<topcam-asic-serial>` / `<wristcam-asic-serial>` —— **跟 SDK 号完全不像**。
> 拿 ASIC 号去填 `serial_no`，**不报错，只是打开另一台相机**（静默失效）。
>
> **怎么读 SDK 号**（板子上现成的办法，不用装 SDK）：
> ```bash
> source /opt/ros/humble/setup.bash
> timeout 12 ros2 run realsense2_camera realsense2_camera_node --ros-args \
>     -p enable_color:=false -p enable_depth:=false \
>     -p enable_infra1:=false -p enable_infra2:=false 2>&1 | grep -i "serial number"
> ```
> 驱动启动时会打印 `Device with serial number <SDK号> was found.`

**朝向与安装**（影响几何，写方案要看）：

| 相机 | 实况 |
|---|---|
| 俯视 | 光轴与台面 **54.1°**（最早是 **25° 掠射**，已重瞄压陡，判据要求 ≤45°）；台面上方 **0.645~0.653 m**（PnP 与深度两路，差 1.2%） |
| 腕部 | **侧装** —— 画面里台面**转了约 90°**（标定时非正方 `patternSize` 必须两向都试） |

> ⚠️ **俯视相机的固定是硬要求**：它一动，外参作废、标签与抓取全偏。
> 已知发生过一次「靶纸被移动约 35 mm」导致 PnP 判据报警。
> 搬动台面上的东西（尤其是靶纸）之后，**要重跑 ⓪① 重出编号图**。

## 2. 网络与访问

### 2.1 三条链路（当前实况 ✅实测 2026-10-02）

```
                     ┌──────────────────────────────┐
   开发机 WSL ──无线──│ wlx3c6a48573453              │
   <ip>/23   │ <board-ip>/22  (DHCP)     │
                     │                              │
                     │        Jetson Orin           │
                     │                              │
   UR 控制箱 ──有线──│ eno1                         │
   <ur-controller-ip>     │ <ip>/24  (静态)    │
                     └──────────────────────────────┘
```

| 链路 | 接口 | 地址 | 用途 |
|---|---|---|---|
| 开发链路 | `wlx3c6a48573453`（USB 无线网卡 RTL8811CU） | `<board-ip>/22` | SSH、开发；**DHCP，租期 2 h，会变** |
| 机械臂 | `eno1`（板载有线） | `<ip>/24` **静态** | 专供控制箱，**不出办公室的网** |
| 控制箱 | —— | `<ur-controller-ip>` | ping 0.26 ms ✅ |

**为什么这么分**：板子**只有一个有线口**，而 SSH 原本也走它 —— 改 `eno1` 就会断线。
分成「无线管开发、有线专供机械臂」之后，**两边互不影响，且机械臂完全不暴露在办公网上**。
（这套方案 2026-09-30 实测走通过，无线吞吐 7.1 MB/s，与有线 7.4 MB/s 持平。）

> ⚠️ **顺序纪律（当年差点把自己锁在门外）**：若日后要重做这个切换，
> 必须**先**确认能经无线地址 SSH 进来（**两个终端**），**再**动 `eno1`。

### 2.2 SSH

```
Host jetson-wifi          # ← 现在用这个
    HostName <board-ip>
    User jetson
    IdentityFile ~/.ssh/board_ed25519
```

- 私钥必须在 **WSL 内**且 `600`；**不要指向 `/mnt/c/...`**（`/mnt/c` 是 777，SSH 会拒）。
- `docs/jetson_ssh_config.txt` 是模板（里面的 IP 可能过期，**以本文件 §2.1 为准**）。
- 板载 mDNS（avahi）被清理脚本关了，**`yahboom.local` 用不了**。
- ⚠️ 别名 `yahboom` **已停用** —— 它原来指向 `<ip>`，那是别人的克隆板。

### 2.3 🔴 控制链路的四个端口，以及**方向是双向的**

| 方向 | 谁发起 | 端口 |
|---|---|---|
| 板子 → 控制箱 | Jetson | `30004` RTDE（状态流）、`29999` Dashboard（管理命令） |
| **控制箱 → 板子** | **机械臂** | **`50001`–`50004`** |

`ur_client_library` 头文件原话：
> *"If the robot cannot connect to this port, External Control will stop immediately."*

**三个直接推论**：
1. **「能 ping 通」完全不够** —— 组网要求是「控制箱能**主动**连到板子的 TCP 50001–50004」。
2. **回连的目标 IP 不是配出来的** —— 驱动里 `reverse_ip` 默认取「板子连 RTDE 用的那块
   网卡的地址」，**由路由决定**。
3. **板子和控制箱必须同网段**。跨网段时方向一可能通、方向二默认被 NAT / 企业防火墙挡掉，
   而**报错会指向 URCap，不会指向网络** —— 现场最容易在这里耗掉一整天。

#### 2.3.1 示教器 URCap 上要填的那个 IP —— **是本板的 `eno1`，别填错**

*Installation* 页三个字段：`Host name` / `Host IP` / `Custom port`。**程序节点靠
`java.net.Socket(hostIp, portNr)` 主动连出** ⇒ 这个框要填的就是**板子 `eno1` 的地址**：

| 字段 | 该填 | 现状（10-03 实测） |
|---|---|---|
| `Host name` | 板子主机名 | `wf` —— **是前负责人那台机器，要改** |
| `Host IP` | **`<ip>`**（板子 `eno1`） | **`<ip>`** —— 实测**不存在**（ping 100% 丢、ARP INCOMPLETE），**要改** |
| `Custom port` | **`50002` 不动** | 已是 `50002` ✅ |

> **为什么是 50002 不是 50001**（免得现场「顺手改一下」）：50002 = 驱动的
> `script_sender_port`，URCap 正是**从它取 `ros_control.urscript`** 的那个口。上游 CB3 文档
> 原话 *"The custom port should be left untouched for now."*，URCap 字节码里的内建默认值
> 也是 `50002`。
>
> **而真正的执行通道不看这个框** —— 回连地址是驱动填进脚本的：
> `socket_open("{{SERVER_IP_REPLACE}}", {{SERVER_PORT_REPLACE}}, "reverse_socket")`
> （`resources/ros_control.urscript:102`）。所以 `Host IP` 改对是**为了拿到脚本**，
> 不是为了让回连通。

### 2.4 ⚠️ 板上的 ufw 必须保持**关闭**

板子自带的 `docs/board/arm-cleanup-sudo.sh` **会启用 ufw，且只放行 22 / 3389 / 5900**
—— **不含 50001–50004**。谁重跑那个脚本，驱动会立刻停，而症状看起来像 URCap 装错了。

当前实测是**关**的（10-03 复核：`/etc/ufw/ufw.conf` → `ENABLED=no`；且从开发机连板子
无监听端口 **0.00 s 回 RST 而非超时**，说明 ufw 不在路径上）。若合规要求必须开：
```bash
sudo ufw allow from <ur-controller-ip> to any port 50001:50004 proto tcp
```

> ⚠️ **别用 `systemctl is-active ufw` 判断这层防火墙有没有在过滤 —— 它报的不是这件事。**
> `ufw disable` **不停单元**（`Type=oneshot` + `RemainAfterExit=yes`），所以关了之后
> `systemctl` 照样报 `active (exited)`。**只看两个东西**：`grep ^ENABLED /etc/ufw/ufw.conf`，
> 或行为（从外面连一个无监听端口：**立刻 RST = 没过滤；超时挂住 = 在丢**）。
> 这个坑在第二十八轮和第七十八轮各踩过一次，**本台账已记两遍。**

## 3. 🔴 安全纪律（**逐字照做，不随任务了结而消失**）

> - **真机只走 Dashboard（29999）只读查询**；**不手搓任何 RTDE 包**，
>   RTDE 通不通让 `ur_robot_driver` 自己去连。
> - **夹爪装在臂上时，写寄存器（初始化 / 开合）= 真机动作。**
>   允许写的**唯一**状态：夹爪**从臂上拆下、放工作台、急停在手边**。
> - **认板子只认模组序列号**（`/proc/device-tree/serial-number`）。
> - **认相机只认外壳标签上的 SDK 号**，用 ASIC 号是**静默失效**。

**这些不是保守，是有事故的**：
- 手搓 RTDE 包（`30004`）**把 URControl 打死过**，控制箱需要人工恢复。
  → 事故全文见 `RESTRUCTURE_PLAN.md` 第五十轮 / `docs/待执行命令-留档.md` **甲-34**。
- 因此 `30001/30002/30003/30004` **一律不碰**；Dashboard `29999` 只发**只读**指令。

**其他常设安全项**：
- 机械臂动作、控制器切换、真机抓取属**高风险操作**：**未经当次明确授权 + 急停就绪 +
  工作区隔离，不得启动真实运动**。
- **写操作前先核对模组序列号**（实验室有克隆板）。
- 不要覆盖板子上已有的目录（`~/yahboom_ws`、`~/ultralytics`、`~/yolo_ros_original`）；
  测试产物只放 `/tmp`。
- 板上的 ufw 保持关闭（§2.4）。

### 3.1 Dashboard（29999）只读指令速查

**已实测可用**的（✅）：

```
robotmode            → Robotmode: RUNNING
safetymode           → Safetymode: NORMAL
programState         → STOPPED null
get robot model      → UR5
get serial number    → <arm-serial>
PolyscopeVersion     → URSoftware 3.15.3.106223 (五月 26 2021)
get loaded program   → No program loaded
```

**这个固件上不认**的写法（别浪费时间）：`version`、`is in remote control`、
`get robot serial number`、`get safety mode`、`get operational mode`。

> ⚠️ **TCP 位姿读不到**。`x/y/z/rx/ry/rz` **只有 RTDE(30004) 有**，
> 而真机不许手搓 RTDE ⇒ **这一组数只能在示教器上看**。

一次性只读查询的最小实现（在**板子**上跑，不要在开发机直连）：

```python
import socket
s = socket.create_connection(("<ur-controller-ip>", 29999), timeout=3)
s.settimeout(3); s.recv(4096)          # 先收欢迎行
s.sendall(b"robotmode\n")
print(s.recv(4096).decode()); s.close()
```

## 4. 几何与尺寸（真机抓取的高度全靠这一节）

### 4.1 `tool0` 在哪

UR 的 `tool0` **原点就在法兰安装面中心**。已验证：
`/opt/ros/humble/share/ur_description/urdf/ur_macro.xacro:457-473` ——
`wrist_3→flange` 与 `flange→tool0` 两个固定关节的 `xyz` **都是 `"0 0 0"`**，
`tool0` 相对 `flange` 只有纯旋转 `rpy="pi/2 0 pi/2"`。

⇒ **`tool0` = 你贴螺栓的那个面**。所有「从法兰量」的长度就是「从 `tool0` 量」。

### 4.2 示教器 TCP 该怎么填（**只有一个槽位时填这一个**）

```
x = 0.0     rx = 0.0
y = 0.0     ry = 0.0
z = 204.2   rz = 0.0        （单位 mm / deg）
```

| 字段 | 为什么 |
|---|---|
| `z = 204.2` | **闭合**时 `tool0` → 指尖 = 大寰官方 `200.2` **+ 本机那层 4 mm 转接件**。见 §4.3 |
| `x = y = 0` | 平行夹爪取**指尖平面中心** |
| `rx = ry = rz = 0` | AG-95 对称安装，工具轴与法兰 `+z` 同向 |

**为什么填闭合值而不是张开值**：
1. **闭合是安全的那一侧** —— 填闭合而实际张开，示教器**显示的指尖比真指尖低
  15.6 mm**，动作会**提前停**；反过来会多扎 15.6 mm。
2. 碰点标定本来就该在**闭合**下做（张开时两指尖分开 95 mm，中点悬空，不是一个实在的点）。
3. 和代码用的是同一条。

**验收方式**：填好后把闭合指尖**轻碰台面**，读位置面板选 **`基座`** 时的 `z`
—— 应当 ≈ **0**。

> 🔴 **读数前先念一遍下拉选的是哪个坐标系。**
> 位置面板那个下拉共三项（`工具` / `视角` / `基座`），**默认停在「视角」**，
> 而「视角」比「基座」高 **399.35 mm**（纯平移）—— 停在它上面会把 `z ≈ 0` 读成 `−395`。

> **示教器上只有一个 TCP 槽位时的换值表**（改之前**先把当前值抄下来**）：
>
> | 什么时候用 | x | y | z | rx | ry | rz |
> |---|---|---|---|---|---|---|
> | 日常 / 碰点标定 | 0 | 0 | **204.2** | 0 | 0 | 0 |
> | 零 TCP 量探针（法兰中心） | 0 | 0 | **0** | 0 | 0 | 0 |
>
> 张开时真要精确读数：临时把 `z` 改成 **188.6**，用完改回 204.2。

### 4.3 `tool0` → 指尖 = **闭合 204.2 / 张开 188.6 mm**

大寰 2024 官方样本给 **184.6（张开）/ 200.2（闭合）**，它的起止线画在
**Ø67 法兰板的底面**上（同一张图另标着板厚 **"5"**、定位凸台 **Ø31.50**、
**P.C.D. Ø50**，法兰局部图注 "Conform to ISO 9409-1-50-4-M6"）
—— 那正是 **UR 螺栓贴合的面**。

| 来源 | 张开 | 闭合 | 基准 |
|---|---|---|---|
| **大寰 184.6 / 200.2** | 184.6 | 200.2 | 法兰板**底面**（AG-95 自己那块板的底） |
| DOBOT 179.64 / 195.21 | 179.64 | 195.21 | 法兰板**顶面**（差 5 ⇒ 与上一行同一点） |
| UR+ 市场页 | 185 | 200 | "from wrist to fingertip" |

**三源互印**（各差 0.2~0.5 mm）⇒ 官方值可靠。**但它量的是
「AG-95 板底面 → 指尖」，不等于「`tool0` → 指尖」** —— 中间还夹着一层：

⭐ **本机多一层 4 mm 转接件。** 前负责人 2026-03-16 的 xacro 把夹爪相对
`tool0` 偏 `0.004`，注释写「**4mm厚度的相机支架**」；腕部相机挂在**同一层**
4 mm 平面上、侧伸 85 mm。而 **Ø67 板半径只有 33.5 mm，够不到 85 mm 外的相机**
⇒ 那一层必然是**外挂件**，`tool0` 与 AG-95 板底面之间夹着它（详见 **§7**）。

**实测印证**：示教器 TCP 填 `200.2`、闭合指尖碰台面，读 `基座` 系
**z = +3.88 mm** —— 正是那 4 mm 的大小（台面本身在 base 系 ≈ 0，见 §4.6）。

> ### `tool0` → 指尖：**张开 188.6 mm / 闭合 204.2 mm**

**取大一档是保守侧**：法兰被放得更高，失手是「**夹空**」而不是「**压桌面**」。
真机首抓若老是夹不到，回退成不加那 4 mm 的 184.6 / 200.2。

### 4.4 `tool0_to_fingertip` ≠ 「法兰→指尖」（**参数名骗人**）

代码里那个参数（`grasp_planner` 的 `tool0_to_fingertip`）语义是
**「法兰 → 抓取时该与方块顶面重合的那个点」**，规划器把它放在 `wz + tool0_to_fingertip`
（`planner_node.py:1288` 接近点 / `:1317` 抓取点），而 `wz` 是**方块顶面**。

> ### `tool0_to_fingertip = (闭合时法兰→指尖) − 方块高`
> ### `place_release_lift  = (闭合 − 张开)`

| | 仿真（Robotiq 2F-85，方块 40 mm） | **真机（AG-95，方块 28.5 mm）** |
|---|---|---|
| `tool0_to_fingertip` | `0.170 − 0.040` = **0.13** | `0.2042 − 0.0285` = **0.1757** |
| `place_release_lift` | `0.170 − 0.160` = **0.01** | `0.2042 − 0.1886` = **0.0156** |

🔴 **两个数都含「方块高 / 行程」，不是纯机械常数。换方块就要重算。**

**这两个值由 `pipeline.launch.py` 随 `camera_source` 自动切**
（`SIM_/REAL_TOOL0_TO_FINGERTIP`、`SIM_/REAL_PLACE_RELEASE_LIFT`），
`grasp_planner.yaml` 里那份是**仿真值**，真机走 launch 参数覆盖。

**首抓时的廉价判据**（不额外花时间）：

| 现象 | 含义 |
|---|---|
| 指尖插进方块 / 压到桌面 | 参数**偏小** ⇒ 往大改 |
| 指尖悬在方块上方、夹空 | 参数**偏大** ⇒ 往小改 |

> 需要精确量时，用 `docs/PROBE_LENGTH.md` 的「零 TCP 碰台面法」
> （工具已备好：`scripts/probe_length.py` + 模板 + 35 条自检）。**它是备用**，
> 触发条件 = 实测老是夹不准。

### 4.5 竖直判据（用臂碰点做标定时必须）

示教器的 `rx/ry/rz` 是**旋转矢量（轴角）**，不是欧拉角 —— 方向 = 转轴，长度 = 转角。

> ### 工具轴竖直朝下 ⟺ **`rz = 0`** 且 **`√(rx²+ry²+rz²) = 180`**（度）

- `rz ≠ 0` 时：**歪角 ≈ 2 × |rz| ÷ π**（度）。`rz = 5` ⇒ 歪 3.2°。
- `rz = 0` 但总长不是 180：**歪角 = 180 − √(rx²+ry²+rz²)**。

⚠️ **差几度就要命**：探针**不在工具轴上**（针尖离轴 46 mm、指尖 48 mm），
⇒ **每歪 1° ≈ 0.8 mm 高度误差**；歪 10° ⇒ 8 mm。

### 4.6 台面在 `base` 系里的高度 ≈ **0**

**臂直接坐在工作台桌面上**，所以台面与 `base_link` 原点几乎同高。

| 量 | 值 |
|---|---|
| 台面在 `base` 系 | **≈ 0**（实测推得 ≈ −0.1 mm） |
| 代码里的 `table_plane_z`（真机） | **0** ← 仿真那份是 `−0.39`，真机必须覆盖 |
| 代码里的 `table_min_z`（真机） | 仍可用 `−0.5`（它现在只是「挡住噪声」的安全护栏） |

**这是怎么量出来的**：TCP 填 `200.2`、闭合指尖轻碰台面，位置面板选 **`基座`**
读到 `z = +3.88 mm`。那 3.88 里有 4 mm 是 **TCP 少填了那层转接件**
（见 §4.3，真值应为 204.2）⇒ 台面本身 ≈ **−0.1 mm**，即 ≈ 0。

> 🔴 **读数前先念一遍位置面板的下拉选的是哪个坐标系。**
> 那个下拉共三项（`工具` / `视角` / `基座`），**默认停在「视角」**，
> 而「视角」=「基座」沿 z 抬高 **399.35 mm**（纯平移，两组的 `rx/ry/rz` 相同）。
> **停在它上面会把 `z ≈ 0` 读成 `−395`** —— 这个坑真实发生过，
> 一度让人以为「臂被垫高了 0.4 m」。
>
> 换算：`基座读数 = 视角读数 + 399.35 mm`（只加在 z 上）。
> 凡是**两点相减**的做法（四点法标 TCP）不受影响 —— 常量偏移自抵消。

### 5.4 AG-95 驱动侧（`grasp_planner/gripper.py`）

| 参数 | 含义 |
|---|---|
| `gripper_backend` | `sim` / `null` / `ag95` |
| `ag95_dry_run` | **默认 `true` = 只读**。翻 `false` 才会写（会动） |
| `ag95_stroke_mm` / `ag95_open_mm` / `ag95_close_mm` | **Python 侧一律用毫米** |
| `ag95_open_is_high` | 手指方向。**已定：`true`**（`0x0202` 读到 1000 = 全开，现场目视确认过） |
| `ag95_port` | 默认走 **`/dev/serial/by-id/usb-FTDI_FT232R_USB_UART_AB0P6UEX-if00-port0`** —— **不要写 `/dev/ttyUSB0`**（插拔会变号） |
| `ag95_baudrate` / `ag95_slave_id` | **115200** / **1**（出厂值，可能被改过，探针要能扫） |

**寄存器（大寰 AG 系列）**：

| 地址 | 作用 | 读/写 | 会不会动 |
|---|---|---|---|
| `0x0100` | 初始化 | 写 | **会动**，0.5–3 s，期间不能发控制指令 |
| `0x0101` | 力 | 写 | 不动 |
| `0x0103` | 目标位置（**0–1000 千分**，不是毫米） | 写 | **会动** |
| `0x0202` | 实时位置回读 | **只读** | 不动 |
| `0x0300` | 存 flash | 写 | 不动 |

**接线现状**：夹爪出来一根 9 芯线 —— **2 根 → FT232R 适配器 → USB → 板子**，
**6 根 → 控制箱**，**1 根 GND 空着**。适配器已实测在位（`0403:6001`，
芯片序列号 `AB0P6UEX`），`jetson` 已在 `dialout` 组。

**解锁写路径的三步（顺序不能反）**：
1. `scripts/ag95_probe.py` 只读探针，确认接线 / 从站号 / 波特率 / 寄存器；
2. ✅ 手指方向已判决（`ag95_open_is_high: true`）；
3. 夹爪**拆下臂、放工作台、急停在手边** ⇒ 才允许 `ag95_dry_run:=false`。

> `pymodbus` 版本：板子是 Python 3.10，`pip install pymodbus` 拿到的是 **3.x**，
> 与 2.x **API 不兼容**（`slave=` vs `unit=`）。`gripper.py` 里已按版本自适应。
